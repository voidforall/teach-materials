SQL 工具箱

ClickHouse 的 SQL 是分析优先的：可合并的聚合、一等公民的数组、还有用一个聚合干掉三个子查询的 argMax。

argMax —— 一趟搞定"每键最新行"

SELECT user_id, argMax(status, updated_at) AS status,
       argMax(balance, updated_at)          AS balance
FROM ledger GROUP BY user_id;

一个聚合，不需要窗口函数、不需要 FINAL、不需要自 join。这是读取追加式/带版本表的惯用法（第 5–6 课）。多个列配同一个 updated_at 排序列，它们保持相互一致。

组合子——每个聚合都有的修饰符

  • sumIf(x, cond)、countIf(cond)——条件聚合替代 CASE-SUM；countIf(a) / count() 一行算比率。
  • uniq/uniqExact——近似（快、定长内存）与精确；uniqCombined 居中。
  • quantile(0.99)(latency_ms)——sketch；quantiles(0.5, 0.99)(…) 一次取多个。
  • -State/-Merge/-MergeState——MV 流水线的部分聚合（第 7 课）。
  • groupUniqArray、topK(10)、any(last(x))——每周都会用的那批。

数组是一等公民

数组天然到来（JSON 字段、漏斗步骤），ClickHouse 对它有一套迷你查询语言：

SELECT user_id,
  arrayFilter(x -> x.event = 'signup', events)  AS signups,
  arraySort(x -> x.ts, events)[1]               AS first_event,
  length(arrayDistinct(arrayMap(x -> x.page, events))) AS pages_seen
FROM user_sessions;

arrayJoin 最特别：把一个数组列展开成多行——把嵌套数据变成普通聚合能嚼的平面行。漏斗分析：windowFunnel（会话内有序事件序列）与 retention（同期群矩阵）是内建的、基于扫描的实现，替代你原本要写五段脚本的分析。

核心要点 ClickHouse 把分析塞进聚合里：组合子后缀管条件和状态，数组配 lambda 管嵌套数据，argMax 管每键最新，windowFunnel/retention 管行为分析。把复杂数仓 SQL（CTE 上叠窗口函数）原样搬过来的直觉常常是错的——通常存在单聚合惯用法。

另外值得知道

  • 窗口函数（OVER/PARTITION BY）存在——用于累计和与排名——但有聚合惯用法时通常更慢。
  • WITH 支持表达式和命名子查询（CTE）。
  • 逐查询 SETTINGS：max_execution_time、max_memory_usage、join_use_nulls——分析查询应自带护栏。
  • 带 SAMPLE BY 键的表可用 sample：在 granule 粒度上做统计有效的抽样。
问 1：不用窗口函数和 join 算"7 日留存"。工具箱里有什么？

retention(cond1, cond2, …)——内建同期群聚合，直接吃首日事件 + 回访事件条件，返回留存矩阵。

问 2：为什么选 countIf 而不是 SUM(CASE WHEN …)？

语义等价，但组合子是原生的向量化形式——更短，内层循环没有分支。

问 3：arrayJoin 能做而 arrayMap 不能的是什么？

它改变行的多重性——把带数组的一行炸成 N 行——而 arrayMap 留在行内。只有 arrayJoin 让下游 GROUP BY 逐元素看到数据。

练习 在 playground 的 github_events 上：按 repo 算今年 WatchEvents 占比，输出占比 top 10。一条 countIf 查询搞定。再试试 topK(10)(repo_name)，注意它算的东西有何不同。
首选资料：聚合函数参考（组合子表）、数组函数、windowFunnel。
