Object Class 这个透镜

一个转变，改变你今后读到每一篇 SCP 的方式。

你已经认识那些名角了 —— SCP-173，你一眨眼就拧断你脖子的混凝土雕像；SCP-096，谁看过它的脸就追杀到天涯海角的"害羞的人"；SCP-682，那头杀不死的爬行动物。你知道这个味道：冷冰冰的临床文件，描述不可能之物。

但有一条"语法"大多数休闲读者都读反了 —— 一旦翻转，整个 wiki 读起来都不一样了。

陷阱："Safe" 听起来无害

天然假设：Safe → 温和，Euclid → 糟糕，Keter → 会杀了你。一个危险度转盘。感觉很显然。但它是错的。

关键思想 一个 SCP 的 Object Class（项目等级）衡量的是收容它有多难 —— 不是它有多危险。是"盒子"的难度，不是"牙齿"的大小。1

wiki 说得很直白：把一个项目归类为 Safe"并不意味着 handling 或激活它不构成威胁"。1一个东西可以既致命又是 Safe。

两个让人豁然开朗的例子

社区的经典思想实验：2

  • 一个按下就毁灭宇宙的按钮 → Safe。锁进抽屉、永远别按。轻而易举地收容。
  • 一只每隔几分钟随机传送到地球某处的猫 → Keter。毫无恶意 —— 但没有任何盒子关得住它。收容是场噩梦。

宇宙毁灭器：Safe。传送猫：Keter。如果等级由危险度决定，这个排序就是荒谬的。它由收容难度决定 —— 所以这个排序完全正确。

你会不断见到的三巨头

SAFE
适度投入即可可靠收容 —— 常因为不被刻意触发就 inert（惰性），或基金会已充分了解它。
"我们知道怎么盖住盖子。"
EUCLID
收容得住，但不可靠 —— 理解不足或天生不可预测。凡是自主、活着或有智能的，默认至少归这里。2
"我们摁着它，但它总在给我们惊喜。"
KETER
极难持续收容；程序繁复、昂贵、随时可能突破收容。Keter ≠ 邪恶。它的意思是"盒子勉强能用"。
"收容是一场进行中的战争。"

为什么"活的 → 至少 Euclid"？把一个活物锁进盒子然后不管，它会饿死或窒息 —— 那是收容失败。有智能的东西还可能斗赢自己的收容程序。2生命让盒子更难维持，所以无论脾气好坏，等级都得升。

再认识一个：Thaumiel

THAUMIEL
被基金会用来收容其他异常的异常。存在本身高度机密 —— 仅限 O5 Council 过目。1
"我们把一只怪物做成了关另一只的笼子。"

在一篇文章里认出 Thaumiel，说明你触到了深层、高权限的设定。还有一整个动物园的稀有与故事专用（"esoteric"）等级1 —— 但 Safe / Euclid / Keter 覆盖你将读到的绝大多数。其余的交给词汇表。

试一试 —— 回忆，别偷看

先在脑子里作答，再展开。从记忆里提取才能记牢 —— 远胜重读。

1. Object Class 实际衡量什么？

收容这个异常有多难。

不是危险度。盒子的难度，不是牙齿。

2. 一小瓶打开就终结所有生命的东西 —— 但轻松密封保存。等级？

Safe —— 因为它轻而易举地被收容。

致命与 Safe 完全兼容。封好的小瓶 = 简单的盒子。

3. 一只随时随机穿墙的友好小狗。等级？

Keter —— 因为没有盒子可靠地关住它。

零恶意，顶级收容噩梦。无害 ≠ 低等级。

4. 为什么有智能的东西从 Euclid 起步？

活着的、会思考的东西会抗拒、会搞乱盒子。

不管它会饿死，还是会斗赢程序。两者都是收容失败。
