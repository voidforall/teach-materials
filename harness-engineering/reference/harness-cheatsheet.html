Harness Engineering — Cheat Sheet

The 8-lesson course on the scaffolding around LLMs, compressed to one printable page: anatomy, context, tools, the loop, skills, guardrails, delegation, evals.

1 · Harness anatomy — Lesson 1

An agent product is not "a model" — it is a program you own, wrapped around a fixed model. Five parts, plus evals watching them all:

PartOne-line role
ModelFixed, probabilistic reasoning core — you don't change it, you feed it.
ContextEverything the model sees this turn: system prompt, history, tool results. A budget, not a landfill.
ToolsThe model's hands — schemas are prompts; descriptions steer behavior.
LoopAct → observe → reflect, repeat — until a designed stop condition fires.
GuardrailsPermissions and hooks: deterministic policy outside the context window.
EvalsThe measurement layer watching all five — every harness change is a code change.

2 · Context engineering — Lesson 2

Every token competes for attention. Competing consumers: system prompt, conversation history, tool results, retrieved documents, scratchpads/todos.

  • Progressive disclosure: load a pointer first (name + description), the body only on invoke, bundled files only on demand. Pay for what the task needs, not what exists.
  • Compaction: when history outgrows the budget, summarize it into structured notes and drop the raw transcript — keep decisions and facts, shed process.
DoDon't
Curate like a budget: every resident token earns its placeDump whole files/logs in "just in case"
Retrieve just-in-time, at the moment of needPreload everything up front
Compact to structured notes on a scheduleLet the transcript grow until attention degrades
Externalize state (todos, files) the model can re-readRely on the model remembering turn 3

3 · Tool design checklist — Lesson 3

  • Description-as-prompt: the description is steering text — say what the tool is for, when to use it, and when not to.
  • Concrete examples in the description beat abstract prose ("Use for 'deploy staging', not 'ship things'").
  • Errors that steer: an error message is feedback — say what went wrong and what to try next, never a bare stack trace.
  • Few high-impact tools: watch the tokens-to-tool-call ratio; merge overlapping tools rather than growing an alphabet.
  • Output contracts: declare the response shape; structured output the next step can parse without re-reading.

4 · The agent loop — Lesson 4

while true:
    response = model(system_prompt, messages, tools)
    if response.has_tool_calls:            # ACT
        for call in response.tool_calls:
            messages.append(run(call))     # OBSERVE
        if not within_budget(): stop("budget exhausted")   # stop: budget
        if error_rate > threshold: stop("too many failures") # stop: errors
        continue                           # REFLECT next turn
    if response.done: stop("task complete")   # stop: done
    if response.asks_user: stop("input needed") # stop: input
    stop("end turn")

An agent without designed stop conditions is a while(true) with a credit card. Workflow vs agent test: who chooses the steps? Your code → workflow; the model → agent. Prefer the workflow.

5 · Skills & progressive disclosure — Lesson 5

Three disclosure levels: (1) name + description always resident (a few tokens); (2) body loaded on invoke; (3) bundled resources (scripts, references) loaded only on demand.

NeedForm
Repeatable multi-step workflow, reused across tasksSkill (pays 0 until triggered)
Stable facts the model should always knowDoc / system-prompt snippet (always resident)
A single action the world must performTool (deterministic behavior, schema-validated)

6 · Permissions & hooks — Lesson 6

LayerGuaranteeUse for
Prompt instructionAdvises — degrades with long contextStyle, priorities, defaults
Permission (ask/allow/deny)Matcher decides whether a call runsSide-effecting tools; narrowest grant wins
HookEnforces — your code runs no matter whatBlocking with a reason that steers the model to the right next action
SandboxRemoves the choice (no network, jailed FS)Belt-and-suspenders under hooks

Common hook points: pre-tool (block/allow/redirect before execution), post-tool (validate or react to results), stop (check work when the loop ends). One approval never extends to the next context.

7 · Subagents & delegation — Lesson 7

A subagent burns its own context window and hands back only the conclusion — latency and tokens traded for a clean main thread.

Delegate whenDon't delegate when
High-read / low-write (research, search, summarize)The task needs shared live context with the main thread
Parallelizable across independent chunksSteps are sequential and interdependent
Self-contained: clear input, one deliverable outputThe conclusion can't be trusted without seeing the work
Context would otherwise bloat the main threadIt's a single quick call — delegation overhead exceeds the work

8 · Evals & iteration — Lesson 8

  • An eval = input (the scenario) + task (what the harness should do) + grader (what counts as pass).
  • Code-graded: deterministic checks (tests pass, file exists, exit code) — prefer wherever possible. Model-graded: a model scores output against a rubric — for open-ended quality; keep rubrics specific.
  • One-variable loop: change one thing → run the suite → read the diff in pass rates → keep or revert. "It feels better" is not a measurement.
