Harness Engineering — 速查表

八课课程"工程化大模型脚手架"浓缩为一页可打印速查：解剖、上下文、工具、循环、skills、护栏、委派、evals。

1 · Harness 解剖 — 第 1 课

一个智能体产品不是"一个模型"——它是一个归你所有的程序，包裹在一个固定的模型外面。五个部分，外加注视着它们的 evals：

部件一句话职责
模型固定的、概率性的推理核心——你改不了它，只能喂它。
上下文模型本轮看到的一切：系统提示、历史、工具结果。是预算，不是垃圾场。
工具模型的手——schema 就是提示词，描述引导行为。
循环行动 → 观察 → 反思，重复——直到某个设计好的停止条件触发。
护栏权限与 hooks：上下文窗口之外的确定性策略。
Evals注视以上五者的度量层——每次 harness 改动都是代码改动。

2 · 上下文工程 — 第 2 课

每个 token 都在争夺注意力。竞争者：系统提示、对话历史、工具结果、检索到的文档、草稿/todo。

  • 渐进披露：先只加载指针（名称+描述），调用时才加载正文，附带文件按需再取。只为任务所需付费，不为存量付费。
  • 压缩（compaction）：历史超出预算时，把它总结成结构化笔记并丢弃原始记录——保留决策与事实，丢掉过程。
要不要
像预算一样经营：每个常驻 token 都要挣得位置"以防万一"地塞入整个文件/日志
即时检索——在需要的那一刻取开头就预加载一切
定期压缩为结构化笔记放任记录增长到注意力退化
把状态外置（todo、文件）供模型重读指望模型记住第 3 轮说过什么

3 · 工具设计清单 — 第 3 课

  • 描述即提示词：描述就是引导文本——说明工具用来做什么、何时用、何时不用。
  • 描述里放具体示例胜过抽象说教（"'deploy staging' 时用"，而不是"发布东西时用"）。
  • 能引导的错误：错误信息就是反馈——说明哪里错了以及下一步试什么，绝不抛裸堆栈。
  • 少而高杠杆的工具：盯住 token 与工具调用之比；合并重叠工具，别养出一个字母表。
  • 输出契约：声明响应结构；输出要让下一步可直接解析，不必重读。

4 · 智能体循环 — 第 4 课

while true:
    response = model(system_prompt, messages, tools)
    if response.has_tool_calls:            # 行动 ACT
        for call in response.tool_calls:
            messages.append(run(call))     # 观察 OBSERVE
        if not within_budget(): stop("budget exhausted")     # 停止：预算
        if error_rate > threshold: stop("too many failures") # 停止：错误
        continue                           # 下一轮反思 REFLECT
    if response.done: stop("task complete")     # 停止：完成
    if response.asks_user: stop("input needed") # 停止：需输入
    stop("end turn")

没有设计停止条件的智能体就是一个带信用卡的 while(true)。工作流 vs 智能体的判据：谁来选步骤？你的代码 → 工作流；模型 → 智能体。优先选工作流。

5 · Skills 与渐进披露 — 第 5 课

三个披露层级：（1）名称 + 描述常驻（几个 token）；（2）正文调用时加载；（3）附带资源（脚本、参考文档）按需加载。

需求形式
可复用的多步骤工作流，跨任务使用Skill（触发前成本为 0）
模型应当始终知道的稳定事实文档 / 系统提示片段（常驻）
需要世界执行的单个动作工具（确定性行为，schema 校验）

6 · 权限与 hooks — 第 6 课

层级保证适用
提示词指令建议——长上下文中会退化风格、优先级、默认值
权限（ask/allow/deny）由 matcher 决定调用是否运行有副作用的工具；授权越窄越好
Hook强制执行——你的代码必然运行带理由的阻断，把模型引向正确的下一步
沙箱直接取消选项（无网络、文件系统监禁）hooks 之下的双保险

常见 hook 触发点：pre-tool（执行前阻断/放行/改道）、post-tool（校验或响应结果）、stop（循环结束时检查成果）。一次批准绝不延伸到下一个上下文。

7 · 子智能体与委派 — 第 7 课

子智能体烧掉自己的上下文窗口，只交回结论——用延迟和 token，换一条干净的主线程。

该委派不该委派
高读 / 低写（调研、搜索、总结）任务需要与主线程共享实时上下文
可跨独立分块并行步骤顺序执行且相互依赖
自包含：输入明确、单一交付物不看过程就无法信任结论
否则会撑爆主线程上下文只是一次快速调用——委派开销超过工作本身

8 · Evals 与迭代 — 第 8 课

  • 一个 eval = 输入（场景）+ 任务（harness 应做什么）+ 评分器（怎样算通过）。
  • 代码评分：确定性检查（测试通过、文件存在、退出码）——尽可能优先。模型评分：由模型按 rubric 给输出打分——用于开放性质量；rubric 要具体。
  • 单变量迭代：只改一件事 → 跑套件 → 读通过率的 diff → 保留或回滚。"感觉更好了"不是度量。

术语速查

术语含义
Harness（脚手架）模型外围的程序：上下文组装、工具、循环、护栏、evals。
上下文窗口模型每轮看到的有限、会退化的 token 预算。
渐进披露先加载指针，需要时才加载细节——skills 的核心机制。
工具 schema工具的名称+描述+JSON 结构；四分之三是提示词。
停止条件枚举出的循环可停方式：完成、预算、输入、错误。
Hookharness 在工具事件（pre/post/stop）确定性执行的代码。
子智能体被委派自包含任务的独立模型+上下文实例，只返回结论。
Eval输入+任务+评分器；让 harness 迭代变安全的度量。
