Context Engineering

The context window is not a database you fill — it is a finite, degrading resource. Every token competes for attention. Curate it like a budget, not a landfill.

Lesson 1 named context assembly as your highest-leverage lever. Here's why it's hard: the window feels huge (hundreds of thousands of tokens) but quality is not flat across it. Long-context recall degrades — the well-known lost-in-the-middle effect means information buried mid-context gets far less attention than what sits at the start or end. And an overflowing window triggers compaction or truncation that silently drops things you assumed were there.

What competes for tokens

At every model call, the harness assembles some mix of:

  • System prompt — identity, rules, output format. Always present, always first.
  • Tool definitions — every tool's name, schema, description. Tens to thousands of tokens, whether used or not.
  • Conversation history — prior turns, tool calls, and their (often huge) outputs.
  • Retrieved material — files, docs, search results pulled in on demand.

Adding "just one more" file or rule is never free: it spends attention that every other token needs.

Keystone Attention is your scarcest resource — curate, don't accumulate. The question is never "can it fit?" but "does this token earn its place right now?" A half-empty window of the right tokens beats a full window of everything.

The levers

Progressive disclosure. Load the smallest useful summary first; pull details only when needed. Agent Skills do this in three tiers: name + description always in context, the body loaded on invoke, bundled files only on demand. Tool definitions can do the same: short descriptions up front, a --help-style detail tool for depth.

Compaction. When history grows past a threshold, summarize older turns into a compact state and drop the raw transcript. Claude Code does this automatically near the window limit; the craft is ensuring the summary keeps decisions, open tasks, and constraints — not chatter.

Structured notes over raw transcript. Instead of relying on the model to re-read its own verbose history, maintain a curated artifact: CLAUDE.md/AGENTS.md for durable project facts, a todo list for working state. The transcript is a record of how you got here; structured notes are the state that matters. Rebuilding context from notes is cheaper and more reliable than scrolling a transcript.

Just-in-time retrieval. Pull a file's content at the moment it's relevant, not "in case". Retrieval beats preloading both on tokens and on lost-in-the-middle risk.

Anti-pattern The ever-growing CLAUDE.md. Teams add rules every week and delete nothing; the file balloons to thousands of tokens, gets loaded into every single turn, and mid-list rules quietly stop being followed. Context files are not documentation — they are instructions competing for attention. Every line must beat "nothing".

Retrieve it

Why can a 200k-token context window still "forget" a rule stated 100k tokens ago?

Attention degrades with bulk.

Recall weakens as context grows, and mid-context material gets the least attention (lost-in-the-middle). The rule technically fits but no longer earns reliable attention — curation, not capacity, is the fix.

Name the three tiers of progressive disclosure in Agent Skills.

Description, body, files.

Name + description load always; the SKILL.md body loads only when invoked; bundled resources load only on demand. Each tier costs more tokens and is paid only when the previous tier earns it.

What must a good compaction summary preserve that a raw transcript would?

Working state, not the journey.

Decisions made and why, open tasks, constraints, and current file state. The back-and-forth that produced them is history — keeping it costs tokens and attention while adding nothing the next turn needs.

Prove it to yourself

Try it — audit your CLAUDE.md, 15 minutes Open the CLAUDE.md or AGENTS.md of a project you work on (write one first if none exists). Apply three cuts: 1) delete anything a competent developer already knows; 2) delete anything only relevant to a past task; 3) merge near-duplicate rules. Target: cut it by half. Then diff behavior over a day — which dropped rules, if any, does the agent actually miss? Those are the only lines that were earning their tokens.
