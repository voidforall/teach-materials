Harness Engineering · 第 2 课上下文窗口 EN

上下文工程

上下文窗口不是一个随便填的数据库 —— 它是一种有限的、会退化的资源。每个 token 都在争夺注意力。把它当预算来经营，别当垃圾场来堆积。

第 1 课指出上下文组装是你杠杆率最高的抓手。它难在哪：窗口看起来巨大（几十万 token），但质量在窗口内并不均匀。长上下文的召回会退化 —— 著名的 lost-in-the-middle（中间遗失）效应意味着埋在上下文中部的信息获得的注意力远少于开头和结尾的内容。而窗口溢出会触发压缩或截断，无声地丢掉你以为还在的东西。

谁在争夺 token

每次模型调用，harness 组装的通常是这些内容的某种混合：

  • 系统提示词 —— 身份、规则、输出格式。永远在场，永远在最前面。
  • 工具定义 —— 每个工具的名字、schema、描述。几十到几千 token，用不用都在。
  • 对话历史 —— 之前的回合、工具调用，及其（往往巨大的）输出。
  • 检索进来的材料 —— 按需拉入的文件、文档、搜索结果。

添加"就多一个"文件或规则从来不是免费的：它花掉的是其他所有 token 都需要的注意力。

关键点 注意力是你最稀缺的资源 —— 做筛选，不做堆积。问题从来不是"装得下吗"，而是"这个 token 此刻配得上它的位置吗？"一个装着正确 token 的半满窗口，胜过一个塞满一切的全满窗口。

四根杠杆

渐进式披露（progressive disclosure）。先加载最小可用的摘要，需要时再拉细节。Agent Skills 分三级做这件事：名字 + 描述始终在上下文里，正文在被调用时加载，捆绑文件按需读取。工具定义也可以照做：描述写短，深度内容交给一个类似 --help 的详情工具。

压缩（compaction）。当历史超过阈值时，把较早的回合总结成紧凑的状态，丢掉原始记录。Claude Code 在临近窗口上限时自动做这件事；手艺在于让总结保住决策、未完成的任务和约束 —— 而不是闲聊。

结构化笔记优于原始记录。不要指望模型重读自己冗长的历史，而是维护一个筛选过的产物：用 CLAUDE.md/AGENTS.md 承载持久的项目事实，用 todo 列表承载工作状态。记录（transcript）是"你怎么走到这里"的痕迹；结构化笔记才是"要紧的状态"。从笔记重建上下文，比翻记录更便宜、更可靠。

即时检索。在文件变得相关的那一刻才拉取它的内容，而不是"以防万一"。检索优于预载 —— token 更省，lost-in-the-middle 的风险也更小。

反模式 无限膨胀的 CLAUDE.md。团队每周加规则、从不删；文件膨胀到几千 token，被塞进每一个回合，列表中部的规则悄悄不再被遵守。上下文文件不是文档 —— 它是在争夺注意力的指令。每一行都必须强过"什么都不写"。

检索一下

为什么 20 万 token 的上下文窗口仍可能"忘掉"10 万 token 之前说过的一条规则？

注意力随体量退化。

随着上下文增长召回会减弱，且位于中部的材料获得的注意力最少（lost-in-the-middle）。规则在容量上装得下，却不再赢得可靠的注意力 —— 解法是筛选，不是扩容。

说出 Agent Skills 渐进式披露的三级。

描述、正文、文件。

名字 + 描述始终加载；SKILL.md 正文只在被调用时加载；捆绑资源只按需读取。每一级 token 代价更高，且只有上一级赚到了它才支付。

一个好的压缩总结必须保住什么 —— 相比原始记录？

工作状态，而非过程。

做过的决定及其原因、未完成的任务、约束、当前文件状态。产生这些的来回对话只是历史 —— 留着它花 token 和注意力，却给下一个回合添不了任何必需的东西。

亲手验证

试一试 — 审计你的 CLAUDE.md，15 分钟 打开你某个在研项目的 CLAUDE.md 或 AGENTS.md（没有就先写一个）。做三次裁剪：1) 删掉任何合格开发者本来就知道的内容；2) 删掉只与过去某个任务相关的内容；3) 合并近乎重复的规则。目标：砍掉一半。然后用一天时间对比行为差异 —— 被删的规则里，智能体真正"想念"的有哪几条？只有那几行，才配得上它们花掉的 token。

接下来去哪

工具定义常常是上下文里最大的隐性消耗者 —— 也是最可工程化的部分。这就是第 3 课：工具设计。

首选阅读 Anthropic《Effective context engineering for AI agents》 —— "有限且退化的资源"的框架，以及压缩、结构化笔记、即时检索（篇幅不长；上面每根杠杆的权威出处）。
有问题？随时问你的老师 —— 问问智能体："你现在的上下文里有什么？代价是多少？"、"举一条我写进 AGENTS.md 但你本来就不会违反的规则"、"你上一次被压缩是什么时候？"
