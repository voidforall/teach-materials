列式布局 — Buffer 速查表

每种 Arrow 数组类型各带哪些 buffer，每个 buffer 有多大。

每个 Arrow 数组就是 buffers + length + null_count + offset。buffer 才是全部故事 —— 那些 API 对象只是架在 buffer 上的视图。本表整理自列式格式规范。

通用规则

  • 所有数值都是小端序；buffer 按 8 字节对齐补齐（各实现以 64 字节对齐为目标）。
  • validity bitmap：每个槽位 1 个 bit，LSB 在前 —— 第 i 个 bit 位于第 i/8 个字节，掩码为 1 << (i%8)。bit 为 1 = 有值，为 0 = null。大小：ceil(length / 8) 字节。
  • buffer 在可以全为默认值时允许省略：null_count = 0 时省略 validity，为空时省略 offsets/数据。
  • offset（数组级的那个）实现了 zero-copy 切片：一个 slice 就是同一批 buffer 换个 offset/length —— 一个字节都不用拷贝。

超出单个数组

  • Dictionary 编码：列 = indices 数组（bitmap + 整数值）+ 独立的共享 payload 数组。null 存放在 indices 的 bitmap 里；切片会让整个 payload 保持被引用；take 只搬运索引。在基数（cardinality）远小于长度时占优。两个 payload/编号不同的 dictionary 在合并/比较前必须先统一（重新编号 = 拷贝）。
  • IPC 消息：Flatbuffer manifest（buffer 在 body 中的偏移/长度对，被省略的 buffer 用零长度条目表示）+ body = 逐字原样的原始 buffer，按 8 字节对齐。流（stream） = 只追加的帧序列；文件（Feather V2）另加一个索引每个 batch 的 footer + 两端的 ARROW1 magic ⇒ 支持随机访问。dictionary 作为独立消息排在使用它的 batch 之前（replace 或 delta 模式）。
  • 逐元素 kernel 的 validity：输出 bitmap = 输入 bitmap 的按位 AND（缺失的 buffer 视为全 1）。add 传播 null，coalesce 吸收 null，聚合跳过 null。kernel 的输出永远是全新的 buffer。

大小速算

  • int64 列，n 行，k 个 null → 总计 ceil(n/8) + 8n 字节。
  • string 列 → 4(n+1) + total_string_bytes（+ bitmap）。每行 4 字节的 offsets 开销正是短字符串被 offsets 摊重的原因。
  • 对任意数组做 [2:5] 切片 → 0 个新字节。
