Offsets（偏移量）与变长布局

字符串没有固定步长 —— 于是 Arrow 存一锅连续的字节汤，外加标明每个值起止位置的栅栏桩。

第 1 课给了你定宽类型的配方：一张位图、一个 values buffer，步长 = 类型宽度。但 "paris" 是 5 字节，"al" 是 2 字节。一个每行步长都在变的 buffer 是没法 SIMD 扫描的。Arrow 的答案就是整门课程反复复用的机制：offsets。

三个 buffer，一锅汤

这是 ["al", "paris", null, "hi"] 按 Arrow 的摆法（Variable-size Binary Layout）：

把槽 1 读出来：data[2:7] = "paris"。槽 2 是 null —— 位图说了算 —— 但它的 offsets 仍然是格式良好的：[7,7]，一个空跨度。null 字符串在构造上长度就是 0，永远不会是一段垃圾跨度。（要与空字符串 "" 区分开 —— 它同样是 [k,k]，唯一能区分两者的就是位图。）

关键点 变长 = 定宽的 offsets + 一锅连续的汤。offsets buffer 拥有完全规整的 int32 步长 —— 它才是你能向量化的东西，而那锅汤从不动窝。正是这套配方（offsets → 子 buffer，或 offsets → 子数组），让 Arrow 得以处理 utf8、binary、list，并通过递归处理一切嵌套类型。

你真正会用到的推广

把字节汤换成一个子数组，你就得到了 list<T> —— Variable-size List Layout。[[1,2,3], null, [4]] 就是：位图（槽 1 为 null）、offsets [0,3,3,4]、以及一个 int32 子数组 [1,2,3,4]。那 list<list<int>> 呢？对子数组再跑一遍配方即可。每层嵌套的代价是一个 offsets buffer —— 没有指针、没有逐节点的分配，这正是把嵌套 Arrow 数据在 C++ 和 Python 之间传递分文不花的原因（第 4 课，zero-copy）。

两个值得知道的边界：

  • int32 offsets 把那锅汤封顶在 2 GB；超过就要用 large_string / large_list 的 int64 offsets（栅栏桩税翻倍）。
  • string_view（C++17 时代的布局）则改为每行内联存储指针+长度 —— 不同的取舍，出现在 DuckDB/Polars 的地盘，不属于核心规范。

练一练

按请求的槽位取出对应的值。栅栏桩习惯 —— offsets[i] 到 offsets[i+1]，先查位图 —— 应该变成本能。连对 5 题。

检索一下

一个 1000 行的 utf8 数组携带多少个 int32 offsets？

1001 个栅栏桩。

永远是 length + 1。n 个值需要 n+1 个边界 —— 就像栅栏桩与栅栏板。1001 × 4 字节 ≈ 4 KB 的纯簿记开销，与字符串本身无关。

一列一百万个短字符串（"OK"、"NO"、……）—— 内存都花在哪了？

offsets 占大头。

每行 4 字节的偏移税 vs 约 2 字节的实际数据。短字符串列是栅栏桩主导的；这是诚实的开销列，不是要治的病（但它正是 dictionary 编码存在的原因 —— 第 6 课）。

null 字符串和空字符串在 buffer 里有什么区别？

就差位图上的那一个 bit。

两者在数据汤里都是零长度的跨度 [k,k]。只有 validity bit 不同：null 为 0，"" 为 1。只看 offsets 你根本分不出来。

[[1,2], [3]] 的布局 —— 说出每个 buffer 的名字。

位图、offsets、子数组。

validity（无 null → 可省略）；int32 offsets [0,2,3]；一个 int32 子数组 [1,2,3]，带自己的（可省略的）位图。与字符串同一套三件配方 —— 只是汤变成了数组。

亲手验证

试一试 — pyarrow，5 分钟 
import pyarrow as pa
s = pa.array(["al", "paris", None, "hi"])
validity, offsets, data = s.buffers()

import struct
off = struct.unpack("5i", offsets.buffer()[:20])   # n+1 个 int32 栅栏桩
print(off)                                          # 先预测：[0, 2, 7, ?, 9]

# 加餐：手工读出槽 3
start, end = off[3], off[4]
print(data.buffer()[start:end])                     # 是 b'hi' 吗？

# 以及 list 推广：
l = pa.array([[1, 2], None, [4]])
print(l.type, l.flatten())                          # flatten() 丢掉了什么？
如果 off[3] 让你意外，回去重读上面的 null 跨度规则。再看一眼 l.buffers() —— list 的 buffer 只有位图 + offsets；整数住在子数组里。
