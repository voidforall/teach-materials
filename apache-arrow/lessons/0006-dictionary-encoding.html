Dictionary Encoding

Repeated values? Store each once, then gossip about them by number.

Lesson 2 left an honest cost on the table: a million rows of "GET" / "POST" / "PUT" pay 4 bytes of offsets + ~4 bytes of soup per row for information that barely varies. Dictionary encoding is Arrow's answer, and it's the third layout trick in your collection (fixed-width, offsets, now this).

Indices + payload

A dictionary<T> array is two arrays in a trenchcoat. The indices array is a plain fixed-width array (Lesson 1 recipe — bitmap + values of some int type) that sits where your column sits. The dictionary** payload is a separate, ordinary array of the value type (Lesson 2 recipe if strings) holding each distinct value once. Column slot i = dictionary[indices[i]].

Decode is two loads: index, then payload slot. And the parts compose with everything you know:

  • Nulls: null-ness lives in the indices bitmap, exactly like any array. A null row is a null index — the payload never contains a "null entry".
  • Slicing: zero-copy, but the slice keeps the full dictionary pinned (Lesson 3 pinning, again). Slicing can't shrink the payload because other rows might still reference it.
  • Compute: kernels special-case dictionaries. take on a dictionary array gathers indices only — payload untouched, still zero payload work. Equality/filter can compare small ints instead of strings. Not everything is smart: some kernels force a decode to plain values first.
Keystone A dictionary array is a fixed-width index column plus a shared payload — so operations on rows become operations on small integers, and the payload is touched by reference, not by value. The payoff scales with repetition ratio: cardinality ≪ length is the win condition. Cardinality ≈ length (UUIDs, floats) makes it pure overhead — an extra indirection, plus a dictionary bigger than the data would have been.

The IPC wrinkle (and why Lesson 4 foreshadowed it)

A dictionary array's payload isn't one of its buffers — it's metadata pointing at a separate array. So IPC carries it out-of-band: dictionary messages (one per field) are written before the record batches that use them, and the batch's buffer manifest (Lesson 4) contains only the indices. Streams of batches share one dictionary message; if the dictionary changes mid-stream, a new dictionary message appears with a flag saying replace or delta (append rows, keep existing numbering — which keeps old indices valid). This is also the trap: two dictionary arrays can only be compared/concatenated cheaply if their payload and numbering match — otherwise Arrow must unify dictionaries (re-map indices, allocate a new payload — a real copy).

Decode it

dictionary[indices[i]] until it's reflex — including the bitmap check. Streak of 6.

Retrieve it

Where does null-ness live in a dictionary array?

The indices bitmap.

The indices array is a first-class array with its own validity bitmap. Null rows have null indices; the payload contains only real distinct values — never a "null entry".

Why is take on dictionary-encoded log levels nearly free?

It gathers indices.

take re-orders rows; the values are unchanged, so only the small int indices are gathered and the payload rides along untouched — the dictionary special-case in the kernel dispatch from Lesson 5.

When is dictionary encoding a net loss?

High cardinality.

Cardinality ≈ length (UUIDs, timestamps, floats): every row points at a different payload entry, so you pay the index bytes AND a payload as big as the original data, plus indirection on every read.

Two chunks of the same column arrive with different dictionaries. What does concat_arrays have to do?

Unify, re-indexing.

Indices only mean something relative to their payload. Different payload/order ⇒ Arrow builds a merged dictionary and re-maps every index — a genuine copy of the index buffers (and possibly payloads). Lesson 3's concat-copies rule, with a dictionary-shaped reason.

Prove it to yourself

Try it — pyarrow, 10 minutes 
import pyarrow as pa, pyarrow.compute as pc

plain = pa.array(["GET", "POST", "GET", "PUT", "GET"] * 200_000)
enc = plain.cast(pa.dictionary(pa.int8(), pa.utf8()))

print(enc.buffers())          # manifest: bitmap + int8 values. Where's the soup?
print(enc.dictionary)         # the payload, all 3 values
print(enc.slice(0, 5).dictionary is enc.dictionary)   # pinned payload?

# compute sees the trick:
import time
t = time.perf_counter(); pc.equal(enc, enc); print("dict cmp:", time.perf_counter()-t)
t = time.perf_counter(); pc.equal(plain, plain); print("plain cmp:", time.perf_counter()-t)

# and decode is just a take:
decoded = enc.cast(pa.utf8())
print(decoded[:5])            # dictionary_take under the hood
The buffer inspection is the lesson: the column's own manifest holds two tiny buffers — and everything big lives in .dictionary.
