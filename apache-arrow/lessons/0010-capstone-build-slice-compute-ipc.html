Build it

# CMakeLists.txt
cmake_minimum_required(VERSION 3.16)
project(capstone CXX)
set(CMAKE_CXX_STANDARD 17)
find_package(ApacheArrow REQUIRED)   # e.g. brew install apache-arrow
add_executable(capstone reference/capstone-build-slice-compute-ipc.cc)
target_link_libraries(capstone PRIVATE Arrow::arrow_static)

Arrow installs a CMake config under lib/cmake/Arrow; if CMake can't find it, point CMAKE_PREFIX_PATH at the install prefix (Homebrew: $(brew --prefix apache-arrow)).

Expected run

$ ./capstone out.arrow
pool before: 0 bytes
pool after build: 128 bytes            # values 32B + offsets/soup + bitmaps, 64-aligned
validity: present, 1B · null_count=1 · offset=0
slice shares values buffer: 1
add(n,5) validity = AND of inputs: 1B
mmap'd read-only buffer: 1 · schema batches: 1
wrote out.arrow — inspect with: xxd out.arrow | head

Exact byte counts may differ (pool granularity, padding) — but every boolean must print 1. Those four lines are the course's theorems, now checked on your machine.

Keystone The capstone is short because Arrow's architecture is deep: one memory format, uniform primitives (buffers, ArrayData, kernels), and everything else composition. When you extend this file for real work — Flight in Lesson 7's shape, dictionaries from Lesson 6, chunked building from Lesson 8 — you'll be adding lines, not learning new models.

Retrieve it (course-wide, interleaved)

The capstone's slice shares a buffer. Which field keeps the parent alive?

The parent shared_ptr.

Buffer's parent reference (Lesson 9's Stop 2) pins the allocation — the slice's ArrayData holds shared_ptrs to the very same Buffer objects (Lesson 3).

Why must add(n, 5) allocate instead of updating n?

Buffers are immutable.

Sharing is only safe because nothing mutates (Lessons 3, 5) — the mmap'd view of an on-disk file could be watching those exact bytes.

The output file's first and last 6 bytes?

ARROW1 twice.

Feather V2 magic at both ends (Lesson 4); OpenFile trusts the footer between them for random batch access.

Encode name as a dictionary before writing. What changes on disk?

A dictionary message.

Indices ride the record batch manifest; the 3-value payload travels as a separate dictionary message before it (Lessons 6, 4).

Extensions — pick one for your first real build

  • Dictionary: cast name via dictionary_encode, confirm the payload appears as its own IPC message (Lesson 6).
  • Chunking: build in 1k-row chunks into a ChunkedArray, watch pool bytes stay flat vs doubling (Lesson 8's simulator, live).
  • Flight: serve the batch over FlightServerBase::do_get and fetch it back (Lesson 7's pyarrow client works against C++ servers — same wire).
