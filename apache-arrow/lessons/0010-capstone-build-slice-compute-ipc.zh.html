Apache Arrow · 第 10 课毕业项目 EN

Build · Slice · Compute · IPC

一个 C++ 文件，不用任何框架，每一行都能追溯到某一课。这就是把整套课程使命宣言变成可执行的代码。

完整源码就在工作区里：reference/capstone-build-slice-compute-ipc.cc（约 100 行，注释详尽）。它构造出你在第 1–2 课手工解码过的那张表，然后对它做 slice、在它上面做计算、写入磁盘，再用 mmap 映射回来 —— 并在每一步断言那个概括了整门课程的性质。

构建它

# CMakeLists.txt
cmake_minimum_required(VERSION 3.16)
project(capstone CXX)
set(CMAKE_CXX_STANDARD 17)
find_package(ApacheArrow REQUIRED)   # e.g. brew install apache-arrow
add_executable(capstone reference/capstone-build-slice-compute-ipc.cc)
target_link_libraries(capstone PRIVATE Arrow::arrow_static)

Arrow 会在 lib/cmake/Arrow 下安装一份 CMake 配置；如果 CMake 找不到它，把 CMAKE_PREFIX_PATH 指向安装前缀（Homebrew：$(brew --prefix apache-arrow)）。

预期运行结果

$ ./capstone out.arrow
pool before: 0 bytes
pool after build: 128 bytes            # values 32B + offsets/soup + bitmaps, 64-aligned
validity: present, 1B · null_count=1 · offset=0
slice shares values buffer: 1
add(n,5) validity = AND of inputs: 1B
mmap'd read-only buffer: 1 · schema batches: 1
wrote out.arrow — inspect with: xxd out.arrow | head

精确的字节数可能不同（内存池粒度、padding），但每一个布尔值都必须打印 1。这四行就是整门课程的定理，如今在你的机器上得到验证。

关键点 毕业项目之所以短，是因为 Arrow 的架构足够深：一个内存格式，一套统一的原语（buffer、ArrayData、kernel），其余一切都是组合。当你为了真实工作扩展这个文件 —— 第 7 课形态的 Flight、第 6 课的 dictionary、第 8 课的分块构建 —— 你只是在加代码行，而不是学新模型。

检索练习（全课程、交错式）

毕业项目里的 slice 共享一个 buffer。是哪个字段让父对象一直存活？

父对象的 shared_ptr。

Buffer 持有的父引用（第 9 课第 2 站）钉住了那块内存 —— slice 的 ArrayData 指向的就是同一批 Buffer 对象的 shared_ptr（第 3 课）。

为什么 add(n, 5) 必须新分配，而不能就地更新 n？

Buffer 是不可变的。

共享之所以安全，正是因为没有任何修改（第 3、5 课）—— 磁盘文件的 mmap 视图可能正在盯着那几个字节。

输出文件的头 6 个字节和末 6 个字节是什么？

两处 ARROW1。

Feather V2 在文件两端都放 magic（第 4 课）；OpenFile 信任夹在中间的 footer 来做随机 batch 访问。

写入前把 name 编码成 dictionary，磁盘上会有什么变化？

多出一条 dictionary 消息。

索引走 record batch 的 manifest；那 3 个值的 payload 作为单独的 dictionary 消息排在它前面（第 6、4 课）。

扩展方向 —— 为你的第一个真实构建挑一个

  • Dictionary：用 dictionary_encode 转换 name，确认 payload 以独立的 IPC 消息出现（第 6 课）。
  • 分块：按每块 1k 行构建 ChunkedArray，观察内存池字节数保持平稳而不是翻倍（第 8 课的模拟器，现场版）。
  • Flight：用 FlightServerBase::do_get 把 batch 服务出去再取回来（第 7 课的 pyarrow 客户端可以直接对接 C++ 服务器 —— 同一条传输协议）。
一手资料 你整门课程一直在引用的 C++ 文档 —— 现在你不需要一节课来陪读它了。
