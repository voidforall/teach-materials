字典编码（dictionary encoding）

值大量重复？那就每个只存一次，之后用编号口口相传。

第 2 课留下了一笔坦白的账：一百万行的 "GET" / "POST" / "PUT"，每行要付 4 字节 offsets + 约 4 字节内容，买到的却是几乎不变的信息。字典编码就是 Arrow 的答案，也是你收藏的第三个布局技巧（定宽、offsets，现在是它）。

indices + 载荷

一个 dictionary<T> 数组是穿一件风衣的两个数组。indices 数组是个普通的定宽数组（第 1 课配方 —— bitmap + 某整型的值），占着你列所在的位置。dictionary 载荷是另一个独立、普通的值类型数组（字符串则用第 2 课配方），每个不同的值只存一份。列槽位 i = dictionary[indices[i]]。

解码就是两次加载：取 index，再取载荷槽位。而且各部分与你已知的一切可组合：

  • null：null 与否住在 indices 的 bitmap 里，和任何数组一样。null 行就是 null 索引 —— 载荷永远不含"null 条目"。
  • 切片：zero-copy，但 slice 会钉住整个 dictionary（第 3 课的钉住，又一次）。切片无法收缩载荷，因为其他行可能还引用着它。
  • 计算：kernel 对 dictionary 有特例。对 dictionary 数组做 take 只收集 indices —— 载原封不动，载荷工作量为零。相等比较/过滤可以拿小整数比而不是字符串。但并非处处聪明：有些 kernel 会强制先解码成普通值。
关键点 dictionary 数组 = 一个定宽索引列 + 一个共享载荷 —— 于是对行的操作变成对小整数的操作，载荷按引用而非按值被触碰。回报随重复率放大：基数（cardinality）≪ 长度是赢面。基数 ≈ 长度（UUID、浮点）时它纯属开销 —— 多一层间接，还多出一个比原数据更大的 dictionary。

IPC 的皱褶（第 4 课为何早有伏笔）

dictionary 数组的载荷不是它的 buffer 之一 —— 它是指向另一个数组的 metadata。所以 IPC 把它带外传输：dictionary 消息（每个字段一条）写在用到它的 record batch 之前，而 batch 的 buffer manifest（第 4 课）里只有 indices。一批批的 stream 共享一条 dictionary 消息；若 dictionary 在流中变化，会出现一条新的 dictionary 消息并带标志说明是替换还是增量（delta）（追加行、保留既有编号 —— 让旧索引仍然有效）。这里也埋着陷阱：两个 dictionary 数组只有当载荷和编号都一致时才能廉价比较/拼接 —— 否则 Arrow 必须统一（unify）字典（重映射索引、分配新载荷 —— 一次真正的拷贝）。

练一练

把 dictionary[indices[i]] 练成条件反射 —— 包括 bitmap 检查。连胜 6 题。

回忆检索

dictionary 数组里 null 与否住在哪？

indices 的 bitmap。

indices 数组是一等数组，有自己的 validity bitmap。null 行的索引为 null；载荷只含真实的去重值 —— 永远没有"null 条目"。

为什么对字典编码的日志级别做 take 几乎免费？

它收集的是 indices。

take 重排行；值没变，所以只有小整数索引被收集，载荷原样随行 —— 这就是第 5 课 kernel 分派里的 dictionary 特例。

什么时候字典编码是净亏损？

高基数。

基数 ≈ 长度（UUID、时间戳、浮点）：每行都指向不同的载荷条目，于是你既付了索引字节，又付了一个和原数据一样大的载荷，外加每次读取的间接跳转。

同一列的两个 chunk 带着不同的 dictionary 到达。concat_arrays 必须做什么？

统一，重建索引。

索引只有相对自己的载荷才有意义。载荷/顺序不同 ⇒ Arrow 构建合并后的 dictionary 并重映射每个索引 —— 对索引 buffer（可能连同载荷）的一次真正拷贝。第 3 课"concat 必拷贝"的规则，换了个 dictionary 形状的理由。

亲手验证

试一试 — pyarrow，10 分钟 
import pyarrow as pa, pyarrow.compute as pc

plain = pa.array(["GET", "POST", "GET", "PUT", "GET"] * 200_000)
enc = plain.cast(pa.dictionary(pa.int8(), pa.utf8()))

print(enc.buffers())          # manifest：bitmap + int8 值。字符串内容去哪了？
print(enc.dictionary)         # 载荷，全部 3 个值
print(enc.slice(0, 5).dictionary is enc.dictionary)   # 载荷被钉住了？

# 计算层看得见这个技巧：
import time
t = time.perf_counter(); pc.equal(enc, enc); print("dict cmp:", time.perf_counter()-t)
t = time.perf_counter(); pc.equal(plain, plain); print("plain cmp:", time.perf_counter()-t)

# 解码就是一次 take：
decoded = enc.cast(pa.utf8())
print(decoded[:5])            # 底层是 dictionary_take
buffer 检查本身就是这一课：列自身的 manifest 只有两个极小的 buffer —— 大块头全在 .dictionary 里。
