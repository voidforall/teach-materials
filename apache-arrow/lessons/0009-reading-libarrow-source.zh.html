Apache Arrow · 第 9 课毕业 EN

阅读 libarrow 源码

八课的理论，一个代码仓库。下面的每一样东西，读起来都应该像老朋友的来信。

这是毕业练习：一次带你走遍 真实的 Arrow C++ 目录树中四个文件的导览，每一处都明晃晃地藏着你早已认识的机制。在 GitHub 上读，或者克隆到本地——git clone --depth 1 https://github.com/apache/arrow，然后住进 cpp/src/arrow/。

第 1 站 — 你一直在用的那个结构体

array/data.h → class ArrayData

找到成员列表。你会几乎逐字看到第 1 课的边车：length、null_count（注意：它可以取 kUnknown——惰性计算）、offset、buffers（一个 shared_ptr<Buffer> 的 vector——第 3 课的引用计数，直接写进了类型里）。然后是两个早就埋下伏笔却没命名的成员：child_data（第 2 课的递归——列表的子数组就住在这里）和 dictionary（第 6 课的带外载荷）。六个字段；到此为止的整门课程。

第 2 站 — 字节的所有者们

buffer.h 与 memory_pool.cc

在 Buffer 里：它就是 {data, size, capacity, parent, ...}——一个视图，不是所有者（这就是 slice 能 O(1) 的原因）。找一找接收父 buffer 的那个构造函数：那正是第 3 课的钉住（pinning），明明白白写成一个字段。在 memory_pool.cc 里：找到 64 字节对齐常量、第 8 课的 bytes_allocated() 记账，以及 jemalloc/mimalloc/系统 malloc 后端切换的地方。

第 3 站 — 一个活生生的 builder

array/builder_base.h 以及 array/ 里的基础类型 builder（builder_primitive.h / 各类型 builder）；位图机制在 util/bit_util.h

要找三样东西：Reserve/UnsafeAppendToBitmap 路径里的容量翻倍（第 8 课的模拟器，变成了代码）；bit_util 里的 BitmapWriter/FirstTimeBitmapWriter——第 1 课的 LSB 优先写入器；以及 Finish() 调用 FinishInternal → ArrayData 构造的地方，草稿在那里被裁剪并转移。如果只读一个函数：读 AppendNull——看它清掉一个位、跳过值槽位。

第 4 站 — 一个 kernel，从头到尾

compute/function.cc（分发）、compute/exec.h（KernelContext、执行循环）、compute/kernels/scalar_arithmetic.cc（你以 pc.add 之名调用过的那个 kernel）

在 function.cc 里：Execute 路径把kernel 签名与实参类型做匹配（第 5 课的分发）。在 scalar_arithmetic.cc 里：一张 ARROW_SCALAR… 风格的宏表，为每个类型对生成一个循环——「一个名字背后几十个 kernel 变体」，是生成出来的。在逐元素的执行路径里：实参的 null 检查——输出 validity = 各输入的 AND，当编译器能证明无需逐元素处理全 null 时，甚至可能是一次真正的按位 AND（bit_util::and_bitmaps）。这就是第 5 课的图，带上了行号。

关键点 libarrow 有约 60 万行，但你刚读过的承重核心只有六个结构体字段、一个视图类型、一个内存池和一条生成出来的循环。 其余部分（类型、kernel、格式、语言绑定）都是用这些原语组合出来的广度。这是对好架构的检验——现在轮到检验你的理解了：你没有向导手册，也走通了它。

检索

在 ArrayData 里，为什么 null_count 可以是「未知」的？

计数被推迟了。

扫描位图数 null 要花 O(n/64)；Arrow 把它推迟到有人来问为止（kUnknown 哨兵值）——构造和切片保持 O(1)。惰性元数据，与省略 buffer 同一种精神。

Buffer 的 parent 字段是为什么存在的？

slice 钉住父对象。

一个 slice Buffer 持有指向它所视图的那块分配的 shared_ptr——第 3 课的「slice 让父对象活着」，落实为一个字段，而不是一条所有权约定。

「一个名字背后几十个 kernel」在机制上是从哪来的？

宏生成的表。

scalar_arithmetic.cc 用代码生成风格的宏展开，为每个类型对产出一条带类型的循环，并把每条循环连同其签名注册进去。分发时只需匹配签名——没有任何运行时代码生成。

练习

动手 — 30 分钟的源码巡游 

# 方便的 grep，在 cpp/src/arrow 下运行：
grep -n "null_count" array/data.h | head
grep -rn "and_bitmaps" compute/ | head
grep -n "AppendNull" array/builder_primitive.h   # 或你选的类型 builder
grep -n "kUnknown" array/data.h
每一个让你觉得难的复选框，都标出了一节值得重读的课——那是间隔检索在指向你的漏洞，而不是失败。
