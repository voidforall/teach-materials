并发服务端：fork 与线程

第 1 课的服务端一次只能服务一个客户端。客户端 #2 一连上，就只能排在内核的 accept 队列里，等你陪 #1 聊完。现在解决它。

第 1 课的循环是迭代式的：accept → 服务 → close → 再来。它诚实、正确，而且一旦两个客户端时间重叠就崩塌。经典的升级路线，按出现顺序：

  • 每连接一进程 —— fork()。子进程继承所有 fd（这正是第 1 课"socket 即文件"的分红），服务完它的客户端就退出。隔离极稳；规模巨大时开销大（一整套进程映像）。
  • 每连接一线程 —— pthread_create。栈很便宜、地址空间共享（既方便又危险），代码仍是阻塞式。
  • 事件循环 —— 一个线程、一大把 fd、从不阻塞。第 6–8 课。
关键认知 并发来自"谁拥有这条连接 fd"，每种模型只是给出不同答案。fork：你的一个副本拥有它。线程：你的一个兄弟拥有它。事件循环：谁也不拥有 —— 谁就绪循环就借用谁。所有设计决策（隔离、共享状态、调度）都从这一个选择推演而出。

fork 模式（最短的正确版）

for (;;) {
    int c = accept(s, NULL, NULL);
    if (c < 0) { perror("accept"); continue; }

    pid_t pid = fork();
    if (pid == 0) {              // 子进程
        close(s);                //   不需要那扇监听的门
        serve(c);                //   阻塞式读写，第 4 课的分帧
        close(c);
        _exit(0);
    }
    close(c);                    // 父进程：交出 fd，转身就忘
}

两行 close 就是本课的课眼。fork 之后，两个进程都握着两套 fd —— 监听者和连接。子进程必须关掉监听者（它不去 accept），父进程必须关掉连接 fd（现在归子进程）。漏掉任何一个，每条连接都会泄漏 fd，直到进程上限干掉你的服务端。还有一处悄悄必需的：signal(SIGCHLD, SIG_IGN)（或一个 waitpid 的处理器），免得退出的子进程变成僵尸滞留。

线程版同构：新线程概念上关掉监听者（线程共享 fd —— 直接把 c 传进去就行），而主线程不关 c；新线程要么 detach 要么被 join，否则这次泄漏的是线程对象。

回忆检索

fork() 刚返回时，一个客户端的连接 fd 有几个？

两个，各进程一个。

fork 复制 fd 表：父子各持一个描述符指向同一个内核 socket。只有最后一个引用关闭，socket 才真正关闭 —— 所以那两行 close 都不能省。

父进程忘了 close 已 accept 的 fd 会怎样？

服务端漏 fd。

每条连接都在父进程里永久留下一个活 fd。连接数过了 "ulimit -n"（常为 1024），accept 就报 EMFILE，服务端对所有人关门 —— 经典的慢性死亡生产事故。

SIGCHLD 为什么要 SIG_IGN？

防子进程成僵尸。

退出的子进程会以僵尸态滞留，直到父进程收割。SIG_IGN 让内核自动收割；另一条路是在处理器里循环 waitpid(-1, ..., WNOHANG)。僵尸不耗内存，但耗 fd/PID 资源，且会累积。

两个线程同时 write() 同一个 socket，有交错风险吗？

整写乱序。

单次 write() 对 socket 缓冲是原子的（不会字节级穿插），但两个线程写谁先谁后是竞态。如果顺序要紧，用一个写线程或加锁 —— 别指望运气。

亲手验证

动手 —— 两个客户端同时在线，20 分钟

把第 1 课服务端的主循环换成上面的 fork 模式，再加 signal(SIGCHLD, SIG_IGN)（包含 <signal.h>）。然后：

cc -Wall server5.c -o server5 && ./server5
# 终端 2 —— 慢客户端：连上就干坐着
nc localhost 5000        # 什么都不输入；保持打开
# 终端 3 —— 并发证明：这个立刻被服务
printf 'still fast\n' | nc localhost 5000
# 终端 4 —— 两个都在线时看进程树
ps -o pid,ppid,command | grep server5

终端 2 闲坐着，终端 3 却秒回 —— 这就是并发。ps 输出里是一个父进程（负责 accept）加每个在线客户端一个子进程。接着轮流删掉那两行 close()，循环重连，看 lsof -p $(pgrep server5) 里泄漏的 fd 越积越多。故意弄坏它一次，就再也不会无意弄坏它。
