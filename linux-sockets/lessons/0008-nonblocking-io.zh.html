非阻塞 I/O

阻塞说"做完了再叫醒我"。非阻塞说"现在能做多少做多少，剩下的以后再说"。EAGAIN 不是错误 —— 它就是全部词汇。

把 socket 拨到非阻塞模式后，每个系统调用都变成状态探针：有数据 read 就给数据，没有就 -1/EAGAIN；内核发送缓冲一满，write 也 -1/EAGAIN。任何调用都不再睡觉。与就绪通知（第 6 课）结合，就得到慢客户端拖不死快客户端的事件循环。

怎么设，以及两面的纪律

// 打开 O_NONBLOCK（两步都要 —— F_SETFL 是整体覆盖，
// 所以必须读-改-写）
int fl = fcntl(fd, F_GETFL, 0);
fcntl(fd, F_SETFL, fl | O_NONBLOCK);

此后每次 read/write 都要按部分完成对待：

  • 部分写是常态。对端读得比你写得慢时内核缓冲会满。你的 write 发出 1000 字节中的 300；剩下的 700 留在该连接的输出缓冲里，订阅 EPOLLOUT，内核一说有空间就续发。学生写事件服务端最常省略的就是这段 EPOLLOUT 舞步 —— 不写它，你就静默丢数据。
  • EAGAIN 是"待会儿"，不是"永别"。标准循环：试 read → 遇 EAGAIN 就回到事件循环；下一次 EPOLLIN 自会再叫你。
关键认知 非阻塞把 I/O 从"等待"变成"轮询"：系统调用回答"现在能给多少"，就绪事件回答"什么时候再来问"。因此每条连接都拥有两个缓冲区 —— 输入缓冲（第 4 课的分帧）和输出缓冲（内核暂时吃不下、还欠着的字节）。事件服务端，就是围绕这两个缓冲区的记账。

水平触发 vs 边缘触发（epoll 的锋刃）

  • 水平触发（默认）："只要还有数据就一直报"。你只读一次、留下残余，下次 epoll_wait 还会再报。宽容。
  • 边缘触发（EPOLLET）："只在每次新到达时报一次"。你必须循环读到 EAGAIN，否则读剩的部分永远不再触发事件 —— 那条连接带着一队列数据永久卡死。更快（唤醒更少），但要求"排空到 EAGAIN"的纪律。

经验法则：先用水平触发；等"循环读到 EAGAIN、常备输出缓冲、处理 EPOLLOUT"刻进本能，再上边缘触发。

回忆检索

write() 1000 字节只返回 300。你该怎么办？

欠着 700，等 EPOLLOUT。

发送缓冲满了 —— 对端不排水。把剩余字节存进连接的输出缓冲并订阅可写事件；EPOLLOUT 一到就续发。忙循环白烧 CPU；丢字节腐蚀协议。

为什么 F_SETFL 之前必须先读标志？

F_SETFL 是覆盖。

F_SETFL 整体替换标志字。只传 O_NONBLOCK 会悄悄清掉该 fd 上已有的其他标志。F_GETFL、按位或、再设 —— 和任何共享寄存器一样，读-改-写。

边缘触发下读了一次留下字节，后果？

连接永久卡死。

ET 只在状态跳变时报 —— 没有新到达就没有新事件。滞留的字节躺在内核队列里，永远等不来下一个 EPOLLIN。所以有此铁律：用 EPOLLET，就循环 read 直到 EAGAIN。

非阻塞 fd 上的阻塞式 read() 永远不会做什么？

睡觉等数据。

这就是全部定义：O_NONBLOCK 把"等就绪"改写成"立刻返回 EAGAIN"。等待被上交 —— 交给你事件循环里的 select/poll/epoll。

亲手验证

动手 —— 会一会 EAGAIN 与 EPOLLOUT，20 分钟 
nc -l 7005 > /dev/null &          # 一个永不读取的水槽：陷阱
python3 - <<'EOF'
import socket
s = socket.create_connection(('localhost', 7005))
s.setblocking(False)               # O_NONBLOCK
payload = b'X' * (50 * 1024 * 1024)   # 50 MB —— 远超任何缓冲
try:
    while payload:
        sent = s.send(payload)     # 部分发送从此是常态
        payload = payload[sent:]
        print('sent', sent, 'left', len(payload))
except BlockingIOError:            # 这就是 EAGAIN
    print('EAGAIN: 内核缓冲满 —— 得等对端排水')
EOF

你刚听到内核说"吃不下了" —— 同样的循环在阻塞 socket 上只会睡觉；在这里你有权决定策略。再补一刀：杀掉水槽（kill %1）—— 不读的对端让你的输出缓冲成为瓶颈。给第 6 课的 epoll 骨架补上输出缓冲 + EPOLLOUT 续发，重演这个场景：慢读客户端拖不住循环，一个字节不丢。这个补丁，就是整个课程的毕业设计。

首选阅读材料 man 7 epoll，"水平触发与边缘触发示例"一节 —— 内核亲自示范排空到 EAGAIN 的循环。
