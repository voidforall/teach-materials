地址与 getaddrinfo

sockaddr_in 是内核勉强容忍的一种说法。真正的地址 API 是 getaddrinfo：域名、端口、IPv4 与 IPv6，一次解析、处处正确。

第 1 课里我们手填了 sockaddr_in —— 学习可以，实战不行。真实程序拿到的是主机名和服务名（"example.com"、"http"），而且不论 IP 版本都得能跑。这就是 getaddrinfo() 的职责。

驯服结构体动物园

  • struct sockaddr —— 所有系统调用都收的通用"地址块"。你从不填写它，只做强转。
  • struct sockaddr_in —— IPv4：family、端口（网络序）、4 字节地址。
  • struct sockaddr_in6 —— IPv6：同构，16 字节地址外加 scope。
  • struct sockaddr_storage —— 一个足够大、对齐正确的联合体，两种 family 都装得下。不知道对面是什么版本时（比如 accept）用它。

还有那条永不消失的字节序规则：凡是通过 socket API 进出结构体字段的东西 —— 端口、地址 —— 一律是大端网络序。人类可读的整数入参用 htons/htonl，出参用 ntohs/ntohl。打印地址用 inet_ntop，解析字符串用 inet_pton —— 永别用 inet_addr（已废弃，无法表达失败）。

关键认知 sockaddr 是通用货币；sockaddr_in/_in6 只是两种方言；getaddrinfo 是替你填表的翻译官。你的代码说"把我连到这个域名和服务"；解析器返回一条由现成的 struct addrinfo 组成的链表 —— 每个可用地址一项（可能 IPv6 和 IPv4 并存）—— 你按序试连即可。

记忆这个模式

struct addrinfo hints = {0}, *res;
hints.ai_family   = AF_UNSPEC;      // IPv4 或 IPv6 —— 交给解析器决定
hints.ai_socktype = SOCK_STREAM;    // TCP

if (getaddrinfo("example.com", "80", &hints, &res)) { /* 失败 */ }

for (struct addrinfo *p = res; p; p = p->ai_next) {
    int fd = socket(p->ai_family, p->ai_socktype, p->ai_protocol);
    if (fd < 0) continue;
    if (connect(fd, p->ai_addr, p->ai_addrlen) == 0) break;  // 连上了
    close(fd);                                                    // 试下一个
}
freeaddrinfo(res);   // 链表是 malloc 出来的 —— 必须释放

对服务端，同一个调用加上 hints.ai_flags = AI_PASSIVE、主机传 NULL，就得到可 bind 的地址（Linux 上默认给 IPv6 的 :: 通配，同时也能收 IPv4）。消费 addrinfo 的三个调用 —— socket、bind/connect —— 的 family/protocol 都取自节点本身，所以一个循环服务两个 IP 版本。这正是它的意义所在。

回忆检索

为什么 getaddrinfo 返回链表而不是单个地址？

名字多址映射。

一个主机名可能解析出多个地址 —— IPv6 与 IPv4 并存，或多个网卡。链表是解析器在说"按优先序试这些"；你的循环逐个尝试，直到 socket+connect/bind 成功。

端口字段为什么必须过 htons()？

线上序不相同。

结构体字段会被原样拷上网络，而网络标准是大端 —— 可你的主机（x86、默认 ARM）是小端。htons/htonl 负责转换；忘掉它，你的服务端就开在一个离谱的端口上（5000 → 0x8813 → 34835）。

客户端可能是 IPv4 也可能是 IPv6 时，accept() 该用什么结构体？

sockaddr_storage 强转。

它的大小和对齐适配任何 family，accept 会把真实 family 写进去；你先判 ss.ss_family 再当 sockaddr_in 或 _in6 用。用普通 sockaddr_in 会截断 IPv6。

AI_PASSIVE 改变什么？谁用它？

给 bind 的通配。

它告诉解析器你要的是用来监听的地址（INADDR_ANY / ::）而不是去连接的地址。服务端设它；客户端从不设。忘掉它，getaddrinfo(NULL, port) 有时会给出没法用的答案。

亲手验证

动手 —— 重写客户端，15 分钟

把你第 1 课工具箱里手填结构体的做法换成真客户端：

// client.c — 用法: ./client 主机 端口 消息
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <netdb.h>

int main(int argc, char **argv) {
    struct addrinfo hints = {0}, *res;
    hints.ai_family = AF_UNSPEC; hints.ai_socktype = SOCK_STREAM;
    if (getaddrinfo(argv[1], argv[2], &hints, &res)) { perror("resolve"); return 1; }

    int fd = -1;
    for (struct addrinfo *p = res; p; p = p->ai_next) {
        fd = socket(p->ai_family, p->ai_socktype, p->ai_protocol);
        if (fd < 0) continue;
        if (connect(fd, p->ai_addr, p->ai_addrlen) == 0) break;
        close(fd); fd = -1;
    }
    freeaddrinfo(res);
    if (fd < 0) { perror("connect"); return 1; }

    write(fd, argv[3], strlen(argv[3]));
    char buf[256];
    ssize_t n = read(fd, buf, sizeof buf - 1);
    buf[n > 0 ? n : 0] = 0;
    printf("echo: %s\n", buf);
    close(fd);
}
cc -Wall client.c -o client
./client localhost 5000 "via getaddrinfo"
# 再连一次真实网络主机；也试试 IPv6 回环：
nc -l 7001 &   ./client ::1 7001 "ipv6 也可以"

在循环里打印 p->ai_family，看看你机器上 localhost 解析出了哪些 family —— 链表，活生生。
