Linux Sockets · 第 1 课基础 EN

Socket 就是一个文件描述符

在学习那些系统调用之前，先记住一个能让一切豁然开朗的观念：socket 就是内核持有的一个"打开的文件" —— 只不过带了个电话号码。

你的目标是写出真正的网络程序，同时理解底层的机器。所以我们先用一句话讲完理论，然后马上动手写、动手跑真实的代码。

当你调用 socket() 时，内核分配一个通信端点，并且 —— 就像文件的 open() 一样 —— 返回给你一个小整数：文件描述符（fd）。你从不直接触碰端点本身，之后的每个系统调用（bind、listen、accept、connect、read、write、close）都只是报出这个整数。这正是 socket 能与 select/poll/epoll 协作的原因，也是它能跨 fork() 继承的原因 —— Unix 的"一切皆文件"把网络也囊括了进来。

关键认知 socket 是一个通过 fd 访问的内核对象；这些系统调用并不亲自把数据搬向网络 —— 它们只是请求内核去做，剩下的事由内核的队列完成。客户端和服务端从不共享内存；内核为每个 socket 维护一条接收队列。read() 不过是"把我的队列倒出来"。

拆解这段不对称：

  • socket() 创建了端点，但它还没有地址。bind() 把它绑定到本地的 IP:端口。客户端通常跳过 bind —— 内核会在 connect 时自动挑一个临时端口。
  • listen() 把 socket 从"主动"翻转为"监听"：它将接受入站连接。内核会建两条队列：一条放进行到一半的握手（已收到 SYN），一条放已完成、正等待你的代码取走的连接。
  • accept() 从队列中弹出一个已完成的连接，并返回一个全新的 fd，专属于这一个对端。监听 socket 继续监听 —— 它是一扇门，而不是一场对话。
  • connect() 是客户端的唯一动作：它驱动 TCP 三次握手，连接建立后返回。

再补一块理论，面试最爱考的那块：TCP 没有消息边界。它是字节流。一次 100 字节的 write() 可能以两次 read()（40 + 60）到达 —— 也可能反过来。这个事实将主宰第 4 课（消息分帧）。

回忆检索

哪个调用把一个新建的 socket 变成可以接受入站 TCP 连接的 socket？

listen。

bind 只分配地址，socket 仍处于"主动"状态；listen 把它标记为被动并分配 accept 队列。accept 生效前两者缺一不可。

一个服务端一次只服务一个客户端。对话期间有几个 fd 存活？

两个。

监听 socket 保持打开（它继续接纳新连接），加上 accept 返回的那条连接专属的 fd。把二者搞混 —— 关掉监听者而不是连接 fd —— 是初写服务端的经典 bug。

客户端一次 write 了 100 字节。服务端一次 read 会返回多少？

不保证 100。

TCP 是没有消息边界的字节流。内核把目前已到达的数据交给 read —— 可能这次 40 字节，稍后再 60 字节。承诺只有"至少 1 字节、至多你要的字节数"。

为什么客户端可以跳过 bind()，服务端却不行？

没人会来连客户端。

对端需要一个稳定、已知的地址去连接 —— 这是服务端的本分。而客户端的源端口只需唯一即可，所以内核在 connect 时自动分配一个临时端口。

亲手验证

动手 —— C 语言，15 分钟

保存为 server.c —— 一个约 30 行的完整 TCP 服务器：

#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <arpa/inet.h>

int main(void) {
    int s = socket(AF_INET, SOCK_STREAM, 0);

    struct sockaddr_in addr = {0};
    addr.sin_family      = AF_INET;
    addr.sin_addr.s_addr = htonl(INADDR_ANY);  // 所有网卡
    addr.sin_port        = htons(5000);        // 主机 → 网络字节序！
    bind(s, (struct sockaddr *)&addr, sizeof addr);
    listen(s, 8);

    puts("listening on :5000 ...");
    for (;;) {
        int c = accept(s, NULL, NULL);      // 阻塞，直到客户端到来
        char buf[256];
        ssize_t n = read(c, buf, sizeof buf - 1);
        buf[n > 0 ? n : 0] = 0;
        printf("got: %s", buf);
        write(c, buf, n);                   // 原样回显
        close(c);                           // 一段对话，就此结束
    }
}

运行它，然后零代码当一次客户端：

cc -Wall server.c -o server && ./server
# 另开一个终端：
printf 'hello sockets\n' | nc localhost 5000

接着让理论变得肉眼可见：在一个终端跑 nc -l 9999，在另一个终端跑 lsof -i :9999（Linux 上可用 ss -tlnp）—— 找到 LISTEN 那一行。再连一个客户端，重跑一遍，找到那条 ESTABLISHED 对。你正看到的，就是上面那幅"两个 fd"的图。
