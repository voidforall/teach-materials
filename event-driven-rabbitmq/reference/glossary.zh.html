词汇表

课程的权威词表。所有课文遵循这里的定义。

Producer（生产者 / publisher 发布者）
调用 publish 把消息发给 exchange 的客户端。它从不直接寻址队列（default exchange 的"名字即 routing key"特例除外）。
Exchange（交换机）
broker 内部的一张路由表。接收 publish 来的消息和它的 routing key，把消息复制进每一条 binding 匹配的队列。类型：direct、fanout、topic、headers。
Routing key
发布者附加在消息上的任意字符串。它的含义完全由 exchange 类型的匹配规则定义；topic 用点分隔的词（order.paid）。
Binding（绑定）
把队列挂到 exchange 上的规则 —— 对 topic exchange 而言是一个含 *（恰好一个词）与 #（零个或多个词）的模式。不匹配任何 binding 的消息会被丢弃。
Queue（队列）
一个准持久的 FIFO 缓冲，保存消息直到消费者确认。竞争消费者共享一条队列；pub/sub 给每个消费者一条自己的队列。
Consumer（消费者）
订阅某条队列的客户端，收到的每条投递都必须 ack（第 2 课）。
Default exchange（默认交换机）
每个 broker 都有的无名 direct exchange：routing key = 队列名。"往队列里发消息"这个民间模型的来源。
Competing consumers（竞争消费者 / work queue）
许多消费者监听一条队列；每条消息恰好被其中一个处理一次。干活的形状。EIP 名称：Competing Consumers。
Pub/sub（发布订阅）
一个 exchange，每个消费者组一条队列，每组拿到自己的拷贝。对事实做反应的形状。EIP 名称：Publish-Subscribe Channel。
Ack（basic.ack）
消费者的裁决"处理完了 —— 删吧"。手动 ack 模式下唯一能从队列删除消息的动作。ack 调用的位置（处理成功之后，而非收到之时）就是消费者的持久化策略。
Nack / reject
"处理不了。"requeue=true 时消息回到队列（小心：立即重投、死循环）；为 false 时被丢弃或 dead-letter（第 4 课）。
Unacked
悬置状态：已投递给消费者、等待裁决。对竞争者不可见但未删除。channel/连接断掉时，所有 unacked 的都会重新入队。
At-least-once delivery（至少一次投递）
手动 ack 买来的保证：一条消息投递一次或多次，绝不零次。推论：消费者必须幂等（idempotent）（同一条消息跑两遍也安全）。
Auto-ack
broker 发送消息的同时就删除它们的模式 —— at-most-once。处理中途崩溃即丢工作。只用于可容忍丢失的流量（指标、行情）。
Prefetch（QoS）
每个消费者 channel 上 unacked 在途消息的上限。生产环境永远别用 0（无限）；要严格公平/顺序用 1；通常 10–100。同时也是竞争消费者的公平机制。
Redelivered flag
broker 对投递过的消息设置的标记。重试逻辑的信号，不能替代幂等。
Publisher confirms（发布确认）
针对 publish 的 broker 侧 ack：broker 对每条已接受（队列 durable 时也已持久化）的消息回确认。没 confirm → 重试 → 可能重复。与消费者 ack 互补，使 at-least-once 成为全系统属性。
Mandatory / returns
发布标志：不可路由（没有 binding 匹配）的消息以 basic.return 退回发布者，而不是被静默丢弃。生产环境里，不可路由的消息应当触发告警。
Idempotency（幂等）
handler 的性质：同一条消息跑两遍的效果等于跑一遍。靠天然幂等（设终态而非算增量）、去重键（唯一消息 ID + 已处理表）、或状态/版本守卫达成。
Deduplication key（去重键）
消息创建时分配的唯一 ID；消费者原子地记录已处理的 ID（ON CONFLICT DO NOTHING）以识别重投。
Dual-write problem（双写问题）
在一个代码路径里既写 DB 又向 broker 发布 —— 没有共享事务，崩溃会产生幽灵事件或丢事件。由 transactional outbox 解决（状态与事件同一事务写入、独立转发）。
Outbox（transactional outbox，事务发件箱）
模式：在与状态变更同一个 DB 事务里把事件持久化到 outbox 表；独立的 relay 带 confirms 发布并标记已发。完整课程：第 6 课。
Dead-letter exchange（DLX，死信交换机）
队列的属性，命名一个接收本队列死信消息的 exchange。触发条件：rejected（requeue=false 的 nack）、expired（TTL 到期）、overflow（超长）。死信消息带 x-death header，经 DLX 以普通路由重新发布。
x-death header
broker 附加在死信消息上的数组：来源队列、原因、计数、时间戳。计数支撑重试上限（"死满 3 次进停车场"）。
Retry ladder（重试阶梯）
退避模式：一串 TTL 队列（10s → 1m → 5m……），每条到期把消息 dead-letter 回工作 exchange。退避期间 broker 持有消息；消费者从不 sleep。一条队列一个 TTL —— 混用按消息 TTL 会队头阻塞。
Poison message（毒消息）
永远无法成功的消息（载荷损坏、引用悬空、handler bug）。靠封顶的 x-death 计数机械化识别；路由进停车场队列交给人。停车场要接告警/ticket，否则是黑洞。
Parking lot（停车场）
重试耗尽后的终点队列。没有消费者；被监控。它不是 bug 追踪器 —— 要喂一个。
TTL（time to live）
按队列（推荐）或按消息的过期。过期即 dead-letter —— 这正是把"TTL 队列 + DLX"变成定时器的机制。
Durability trinity（持久性三件套）
durable exchange + durable（quorum）queue + persistent 消息（delivery_mode=2）—— 三者齐备，否则被 confirm 的消息也会在 broker 重启时消失。默认值不是这个组合。
Quorum queue
带复制、基于共识的队列类型；重要数据的现代默认。对应用代码的影响 ≈ 零；是对 classic queue 的持久性/运维升级。
Consistent-hash exchange
exchange 类型（内置插件），按 routing key 的哈希在绑定的队列间路由 —— 并行前提下的实体级顺序。RabbitMQ 版的 Kafka partition。
Tolerant reader（宽容读者）
忽略未知字段、对缺失可选字段取默认值的消费者 —— 使增量 schema 变更无需协调。破坏性变更配合带版本的 routing key（order.placed.v2）。
Transactional outbox（含 relay）
让"提交状态 + 发布事件"安全的模式：两行记录在同一个 DB 事务里提交；独立 relay 把待发的 outbox 行带 confirms 发布并标记已发。relay 可能重复发布 —— 消费者保持幂等。relay 实现：轮询器或 CDC（Debezium）。
Saga
跨服务的业务流程，建模为一串本地事务，每步带自己的 outbox。没有原子性跨服务；取而代之，每个正向步骤配补偿动作（compensating action）（reserve ↔ release、charge ↔ refund）。故障被恢复，不被预防。
Choreography（编舞）
纯事件驱动的 saga 协调：服务互相响应对方的事实；流程从 binding 中涌现。低耦合，但步骤一多流程逻辑就散落。经验法则：≤3 步。
Orchestration（编排）
由一台状态机协调 saga：发命令、收结果，显式拥有失败分支与补偿。流程集中可审计。步骤 ≥4、有分支、超时、涉及钱时用它。败法：orchestrator 长成上帝服务。
Compensating action（补偿动作）
已完成 saga 步骤的撤销（退款、释放、取消）。失败时按倒序执行。有些步骤没有有意义的补偿 —— 交给人，不交给自动化。
Eventual consistency（最终一致性）
跨服务状态异步收敛。技术上由幂等 + 版本守卫兜住；剩下的负担在 UX —— 建模 pending 状态、不伪造同步应答、把 lag 当 SLA 监控。
Log of record（记录日志，相对任务队列）
选 broker 的那根轴：处理之后怎么办？任务队列ack 即删（做完即弃的工作 —— RabbitMQ、SQS）；记录日志保留、可从任意 offset 重读（历史 —— Kafka）。成熟系统常常两者都用：Kafka 做记录流，接缝处配 RabbitMQ 工作队列。
Offset（Kafka）
消费者组在每个 partition 上的读取位置 —— ack 的对应物，按批提交、从不按消息。失败处理与重试都在应用层（retry topic）。
Consumer group（Kafka）
Kafka 的竞争消费者：成员共享一个组，partition 在成员间分配 —— 并行度以 partition 数为上限，partition 内严格有序。独立组各自读全量日志（pub/sub 形状）。
Visibility timeout（SQS）
SQS 版的 ack：消息被取走后隐藏 N 秒；未按时删除就重新出现。at-least-once 换了衣服，幂等账单照付；调这个计时器替代调 prefetch。
Redrive policy（SQS）
SQS 内置的停车场：maxReceiveCount 之后消息转入 dead-letter queue。第 4 课阶梯的最省心版本。
Event（事件 / 事实 fact）
对已发生之事的通知（order.created）。与命令（command）（charge.card，请求某事发生）相对。决定谁拥有命名与载荷。
