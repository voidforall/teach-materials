Value-Based Methods: DQN

Q-learning learns a table of "how good is this action here" and picks the argmax. DQN is that table replaced by a neural net — plus two tricks that keep it from eating itself.

Value-based methods never touch a policy directly. They learn Q(s, a) — the expected discounted return of taking action a in state s and acting optimally after — and derive the policy as argmaxa Q(s, a). The update is the Bellman backup:

r + γ · max<sub>a'</sub> Q(s', a')  −  Q(s, a)   →  loss (TD error)

With a network approximating Q, this bootstrap is unstable: the target moves because the network itself computes it. The original DQN paper (Mnih et al., 2015) stabilized it with two mechanisms, and both are non-negotiable in any competition implementation:

  • Replay buffer — store transitions, sample random minibatches. Breaks the temporal correlation of self-play trajectories and reuses each expensive simulated step many times.
  • Target network — a frozen copy of Q computes targets; it is synced every N steps. The chase-me-myself pathology becomes a chase-a-slowly-moving-copy pathology, which converges.

Two standard upgrades fix remaining biases. Double DQN (van Hasselt et al., 2015) decouples selection from evaluation: the online net picks the argmax action, the target net scores it — killing the systematic overestimation of max. Dueling heads (Wang et al., 2015) split Q into V(s) + A(s,a), so states with the same value for every action don't produce noisy phantom action preferences — useful in Kaggle sims where many turns are forced.

Action masking, the Kaggle way

Sims reject illegal moves (or worse, waste your turn on them). Don't let the network learn legality — mask before the argmax:

q = qnet(s)                      # shape [n_actions]
q[~valid_action_mask(s)] = -inf  # or -1e9
a = argmax(q)                    # greedy; add ε-greedy over valid set

This composes cleanly with dueling heads and is the single most common bug source in beginner DQN submissions: an agent that must choose among 7 legal Connect X columns should never have columns 8+ (or full ones) in its argmax.

Keystone DQN = Q-learning + replay buffer + target network; everything else is bias reduction. If your value-based agent diverges, check these two stabilizers before touching hyperparameters — and mask invalid actions before the argmax, not after the environment rejects them.
Anti-pattern Updating the target network every step (or forgetting the replay buffer). With a moving target the TD error never settles — loss oscillates, the Q-values inflate, the agent collapses to one action. Symptoms: Q-values drifting far beyond any plausible return; epsilon-greedy agent that stops exploring but also stops winning.

Retrieve it

Why does DQN need a replay buffer at all — what breaks without it?

Correlated, non-reused samples.

Consecutive self-play transitions are highly correlated, which violates the i.i.d. assumption of SGD and causes catastrophic forgetting. Random sampling from a buffer decorrelates batches and reuses each simulated step many times — critical when steps are expensive.

What specific bias does Double DQN remove?

Overestimation of max-Q.

maxa Q(s', a) selects and scores with the same noisy values, so noise biases the target upward. Decoupling selection (online net) from evaluation (target net) removes most of that bias without changing the architecture.

Your sim has 7 legal actions this turn, 3 the next. Where does legality enter the pipeline?

Mask Q-values before argmax.

Set invalid entries to −∞ (or a large negative) so both greedy action choice and ε-greedy exploration operate only on the legal set. Making the network "learn" legality from punishment signals wastes capacity and destabilizes training.

Prove it to yourself

Try it — 20–30 minutes, reading real code Open CleanRL's single-file implementation at docs.cleanrl.dev — dqn.py. Find and annotate: (1) the replay buffer append and sample calls; (2) the target-network sync (`target.load_state_dict`); (3) the TD loss line — note it uses plain max, not Double DQN. Then modify it: implement the 3-line Double DQN change and add an action mask hook (a function taking the observation and returning a validity mask applied to q_values before argmax). Check the Spinning Up Q-learning part 2 page if the math feels shaky.
