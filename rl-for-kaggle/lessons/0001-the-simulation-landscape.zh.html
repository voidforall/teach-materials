模拟竞赛的版图

模拟竞赛是 Kaggle 上唯一一种「你的提交要和其他提交对战」的赛制。仅这一个事实，就决定了你应该使用的全部技术。

普通 Kaggle 比赛是用模型去拟合一个固定的测试集。而在模拟竞赛——Connect X、Halite、Kore、Santa 解谜系列、Lux AI Prize——中，你提交的是一个智能体（agent）：平台会让它在天梯上与其他智能体配对对战。每一局是一个回合（episode）；比赛结果更新技能评分（Kaggle 采用类 TrueSkill 评分）；奖牌取决于比赛截止时的排名。

智能体的接口极其精简：一个 Python 文件暴露 def agent(obs, config)，每回合被调用一次并返回动作，且受严格的单步时限约束（常常远少于一秒）。提交之前，你可以用官方的 kaggle-environments 包在本地跑对局。

四类工具箱

  • 手写策略——人类编写的规则与启发式。便宜、快、可调试，是所有冠军方案的地基或引导起点。
  • 搜索——minimax、alpha-beta、蒙特卡洛树搜索（MCTS）。当分支因子小、局面评估便宜时必胜。Santa 2020 被高效率的搜索横扫，而不是深度强化学习。
  • 强化学习——通过（自我）对局学习策略以最大化奖励。当状态空间巨大、手工特征失效时获胜：Lux、Halite、Kore。
  • 混合——RL 或神经网络出提议、搜索做验证；或在学习策略不可靠时回退到规则。多数获奖方案都是混合体。

本课程要教的纪律是：按游戏的分支因子、状态规模和时间预算选工具箱——而不是按潮流。深度强化学习昂贵且难调；如果纯搜索能解决这个游戏，它就解决得更好。

关键点 你不是在拟合测试集，而是在为一条满是对手的天梯打造一个玩家。模型、时间预算、确定性——所有设计决策都源于「基于回合的对抗式评估」，而不是独立同分布的测试行。
反模式 因为游戏「看起来很 AI」就上深度强化学习。Santa 2020 的顶尖方案是位压缩状态加快速搜索；深度 RL 方案输给了它们。选择能赢的最便宜工具箱，只有在确证它赢不了时才升级。

回忆检索

模拟竞赛的提交物是什么？

一个智能体文件，而非模型。

一个每回合被调用一次的 Python 入口，参数是 observation 和 config；平台让它与其他智能体进行对局并按结果评分。训练在离线完成——提交物只做推理。

说出模拟竞赛的四类工具箱。

规则、搜索、学习、混合。

手写策略、树搜索、强化学习，以及它们的组合（如网络先验引导搜索，或规则兜底学习策略）。真实的排行榜由混合方案主导。

什么时候深度 RL 不是首选？

搜索就足够时。

分支因子小、状态评估便宜的游戏适合 alpha-beta 或普通 MCTS。只有当状态空间太大或特征太微妙、规则与搜索无法胜任时，深度 RL 才对得起它的成本。

亲手验证

试一试 — 约 15 分钟 pip install kaggle-environments，然后在本地跑一局两个内置智能体的 Connect X（env.run([agent1, agent2]) 与 env.render(mode="ipython")）。检查 obs 和 config 里到底有什么——第 3 课你封装的正是它。
