The Simulation Competition Landscape

Simulation competitions are the only Kaggle format where your submission plays a game against other submissions. That single fact changes every technique you should reach for.

In a normal Kaggle competition you fit a model to a fixed test set. In a simulation competition — Connect X, Halite, Kore, the Santa puzzle series, the Lux AI Prize — you submit an agent: a file the platform matches against other agents on a ladder. Each match is an episode of a game; results update a skill rating (Kaggle uses a TrueSkill-style rating); medals come from your rank when the competition closes.

The agent contract is minimal: a Python file exposing def agent(obs, config) that returns an action, called once per turn under a strict time limit (often well under a second). You can run episodes locally with the official kaggle-environments package before ever submitting.

The four toolboxes

  • Handcrafted policy — rules and heuristics written by a human. Cheap, fast, debuggable, and the foundation every winner builds on or bootstraps from.
  • Search — minimax, alpha-beta, Monte Carlo tree search over the game tree. Wins when the branching factor is small and evaluation is cheap. Santa 2020 was swept by wall-clock-efficient search, not deep RL.
  • Reinforcement learning — learn a policy by playing (self-play), maximizing reward. Wins when the state space is huge and handcrafted features fail: Lux, Halite, Kore.
  • Hybrid — RL or a neural net proposing moves, search verifying them; or a rules fallback when the learned agent is uncertain. Most winning entries are hybrids.

The discipline this course teaches: pick the toolbox by the game's branching factor, state size, and time budget — not by fashion. Deep RL is expensive and finicky; if plain search solves the game, it solves it better.

Keystone You are not fitting a test set; you are building a player for a ladder of adversaries. Every design decision — model, time budget, determinism — follows from the episode-based, adversarial evaluation, not from i.i.d. test rows.
Anti-pattern Reaching for deep RL because the game feels "AI-ish". In Santa 2020, top solutions were bit-packed states and fast search; deep-RL entries lost to them. Choose the cheapest toolbox that can win, and only escalate when it provably can't.

Retrieve it

What does a simulation competition submission consist of?

An agent file, not a model.

A Python entry point called once per turn with the observation and config; the platform matches it against other agents in episodes and rates the results. Training happens offline — the submission only runs inference.

Name the four toolboxes for sim competitions.

Rules, search, learning, hybrids.

Handcrafted policy, tree search, reinforcement learning, and combinations (e.g. network priors guiding search, or a rules fallback guarding a learned policy). Hybrids dominate real leaderboards.

When is deep RL the wrong first choice?

When search suffices.

Small branching factor and cheap state evaluation favor alpha-beta or plain MCTS. Deep RL earns its cost only when the state space is too large or features too subtle for search and rules alone.

Prove it to yourself

Try it — 15 minutes pip install kaggle-environments, then run a Connect X episode between two built-in agents locally (env.run([agent1, agent2]) and env.render(mode="ipython")). Inspect what obs and config actually contain — you will wrap exactly this in Lesson 3.
