毕业项目流水线

所有内容汇于一处：把 Connect X 封装成 Gym 环境、自博弈训练智能体、对对手池评估、交付一个能通过校验的提交文件。

这是整门课拼成的一张施工图，本周就能在 Connect X 上跑通——小到能做完，真到能泛化。每个阶段都标注了讲授它的课程。

阶段 1 — 环境（第 3 课）

阶段 2 — 学习器（第 5–7 课）

按动作空间大小和时间预算选型：DQN（CleanRL 的 dqn.py——7 个动作、掩码 Q 头）是一个周末能做完的选项；AlphaZero-lite（AlphaZero_General 血统——PUCT 搜索 + 按访问量训练的策略/价值网络）是奖牌级选项，也是更好的练习。按第 8 课可选：先克隆 negamax 热启动。自博弈从第一步起就对快照池打——永远不要只对最新策略。

阶段 3 — 联赛（第 9 课）

每晚：候选者对池子（快照 + negamax + 你的脚本机器人），各 200 局、双边、TrueSkill 表。只有置信区间明确占优才晋升。这张表就是你的实验日志——每个训练决策都应能由表中的一行来支撑。

阶段 4 — 提交文件（第 1、3 课）

提交物是单个 submission.py：只做推理，不训练、不联网。权重直接烘进去——pickle 进文件，或作为 Kaggle 数据集挂在旁边。

# submission.py — 整个智能体
import pickle
weights = pickle.loads(b"...")   # 或从附带数据集 np.load
net = load_net(weights)          # 在 import 时构建，而非每回合

def agent(obs, config):
    board = encode(obs, config)          # 与训练完全相同的平面！
    return int(net.act(board, mask=legal(obs)))

Kaggle 陷阱清单

  • 每回合超时：首回合与其后每回合有各自预算（Connect X：秒级，不是分钟级）。测最坏情况的推理耗时，不是平均值；网络在 import 时构建，绝不放进 agent() 里。
  • 通过校验：尽早用平凡智能体提交一次，把流水线跑通；这里的错误是格式问题，不是智力问题。
  • 提交时不训练：文件必须是确定性推理；任何「回合内学习」的花招都得塞进回合预算和规则之内。
  • 确定性种子：固定种子保证可复现，但要验证评测方换种子时智能体依旧正常。
  • 文件大小：查清上限（内联文件常约 100 KB，带 utility script/数据集约 20 MB）——必要时压缩或量化权重。
  • 推理离线：没有网络；所有依赖打包或附带。
关键点 Kaggle 智能体既是学习问题，也是交付问题。超时、校验失败、偏离训练编码的最强策略，得分恰好为零。第一周就把流水线端到端跑通，然后再在一个循环里持续改进。
反模式 把研究 notebook 当智能体提交。训练脚本要建数据集、起环境、下模型——这些在评测沙箱里统统不存在。提交物是一个文件、import 时加载、每回合推理，仅此而已。

回忆检索

为什么网络必须在 submission.py 的 import 时构建？

构建开销会吃掉一整回合。

在 agent() 里建模型会把启动开销记到单个回合的预算上，可能瞬间超时。import 时构建只付一次，且在计时开始之前。

为什么候选者要对池子评估，而不是只对上一版最优？

单一对手藏盲区。

赢下最新快照是必要非充分条件——多样池中的硬克星风格会暴露头对头对局掩盖的退化。联赛里的每一行才是证据。

什么编码 bug 会悄悄毁掉一次提交？

推理与训练不一致。

若提交时的棋盘编码与训练时不同（平面顺序、视角、掩码），网络收到的是分布外输入，走出昏招——却照样通过校验。

亲手验证

动手 — 真正的毕业项目 搭建流水线：gym 封装 → DQN 或 AlphaZero-lite 自博弈 → 对 negamax 与快照的联赛表 → submission.py。提交到 Connect X。然后把你本地联赛胜率与约 50 局后的 Kaggle 实际评分对比——这个差距就是你评估水平度量。起点：kaggle-environments 与 CleanRL 的单文件实现。
