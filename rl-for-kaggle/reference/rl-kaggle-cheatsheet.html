RL for Kaggle — Cheat Sheet

The 10-lesson course on one printable page: which technique when, the core update rules, reward-shaping discipline, self-play and submission checklists, glossary. Start at Lesson 1.

1 · Which technique when

TechniqueUse whenWatch out
Handcrafted policyRules are known; short time budget; baseline to beatHard ceiling; becomes your BC teacher, not your agent
Tree search (minimax/negamax)Small game tree, cheap simulation (Santa-style puzzles, Connect X)Branching × depth = wall clock; needs good eval function
DQNSmall discrete action space; single net, replay buffer simplicityOff-policy instability; poor with huge/masked structured actions
PPOSelf-play loops, structured actions, want simple and robustOn-policy = data hungry; entropy collapse if bonus too small
AlphaZero-styleMedal push on any sim you can mirror fast; policy+value+MCTSCompute cost; sim speed is the bottleneck, write your own
Imitation bootstrapAlways, if any scripted expert exists — warm start before RLBC ceiling & distribution shift; anneal expert data away

2 · Core update rules

DQN target:     y = r + γ · Q_target(s', argmax_a Q_online(s',a))   # double DQN
PPO objective:  L = E[ min(ρ·A, clip(ρ, 1−ε, 1+ε)·A) ]  with ρ = π(a|s)/π_old(a|s)
MCTS (PUCT):    argmax_a Q(s,a) + c_puct · P(s,a)·√ΣN / (1+N(s,a))
  • DQN machinery: replay buffer, target net (slow sync), ε-greedy, action-masked Q-heads.
  • PPO extras: GAE(λ) advantages, entropy bonus, value-function loss, few epochs per batch.
  • AlphaZero: train policy on MCTS visit counts (improved targets), value on game outcome.

3 · Reward shaping rules of thumb

  • Terminal win/loss ±1 is the only non-negotiable term — it is the leaderboard metric.
  • Prefer potential-based shaping: r' = r + γΦ(s') − Φ(s) — provably policy-invariant.
  • Heuristic shaping (score deltas, survival): small, monitored, faded to zero as win-rate climbs.
  • Alarm bell: shaped reward up while true win-rate stalls or episodes stretch = reward hacking.

4 · Self-play checklist

  • Snapshot every N checkpoints into the opponent pool — never train vs latest only.
  • Mix styles: snapshots + scripted bots + starter agents (+ public bots if rules allow).
  • Fast sim: wrap as Gymnasium env; write your own mirror if the official runner is slow.
  • Swap seats in asymmetric games; fix seeds; vectorize parallel envs.
  • Promote snapshots only on league evidence, not one head-to-head win-rate.

5 · Submission checklist

  • Per-turn time budget respected — measure worst-case inference, not average.
  • Build nets at import time; never inside agent(obs, config).
  • Passed Kaggle validation with a trivial agent first (pipeline before intelligence).
  • Inference only: offline weights baked in, no training, no network at submit time.
  • Deterministic seeds — and still correct when the harness seeds differently.
  • File size under cap (~100 KB inline / ~20 MB with attached files); quantize if needed.
  • Encoding at inference identical to training (planes, perspective, masks).

6 · Glossary

MDPMarkov decision process: (state, action, reward, transition) — the frame you impose on the sim.
POMDPPartially observable MDP: you see only your view (Lux); memory/recurrent nets or search over beliefs.
Self-playAgent trains against itself or its own past versions — generates unlimited opponents.
Snapshot poolFrozen past checkpoints used as training opponents and eval benchmarks.
LeagueAll-vs-all evaluation of a population with Elo/TrueSkill ratings; miniature AlphaStar.
GAEGeneralized advantage estimation: λ-blended TD residuals for low-variance advantage.
PUCTPredictor + UCT: MCTS selection rule trading value, prior, and visit counts.
Behavioral cloningSupervised imitation of an expert's actions; warm start with a hard ceiling.
Elo / TrueSkillPairwise skill ratings from win/loss; TrueSkill adds uncertainty (σ) — Kaggle's ladder flavor.
