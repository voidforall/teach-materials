The Defender's Stack

You have spent eight lessons attacking; now learn the wall you are attacking — because the CrowdStrike puzzles are scored by defenses, and every defense has a seam.

Every layer in this lesson exists because a real attack worked once. The OWASP LLM Top 10 catalogs the failures; the defender's stack is the industry's layered answer. As a red-teamer you must know this stack cold, for one reason: the defenses determine what the puzzles punish. A payload that trips a canary costs you points; a payload aimed at an unguarded layer costs you nothing.

Layer 1 — Instruction hierarchy training

Model vendors train the model itself to privilege system prompts over user turns, and user turns over retrieved content (instruction hierarchy, the priority ordering of who the model obeys). This is real and it stops naive ignore previous instructions attacks — which is why Lesson 2's direct injections mostly stopped working. But it is training, not enforcement: it is probabilistic, degrades under obfuscation and long contexts, and says nothing about semantically convincing content in retrieved data. Treat it as friction, not a wall.

Layer 2 — Spotlighting and delimiting

Microsoft's spotlighting defenses (Hines et al., 2024) mark untrusted content so the model can tell data from instructions: delimiting wraps retrieved text in quotes or XML tags, datamarking prefixes every line with a token like <UNTRUSTED>, and encoding base64-encodes the content so it reads as a blob, not as commands. The attack implication is exact: any payload that closes or spoofs the delimiter — a stray </untrusted> in your injected web page — targets the gap between "marked" and "understood".

Layer 3 — Input and output classifiers

Guardrail classifiers score the prompt before it reaches the model and the completion before it leaves. Input filters catch known jailbreak patterns; output filters catch secrets, PII, and forbidden content. Lesson 7 covered evasion; the defender's dilemma is that both filters must be conservative to avoid breaking the product, and every conservative threshold is a channel — encode the payload (Lesson 4), split it across turns, or phrase the exfil as routine output.

Layer 4 — Least-privilege tools and egress control

OWASP's "excessive agency" entry pushes defenders to give agents least privilege (minimum permissions needed for the task): read-only where possible, scoped API keys, and egress allowlists that restrict which hosts the agent may contact. This is the layer that most changes your attack plan: if outbound requests go only to an allowlisted domain, your markdown-image exfil (Lesson 6) must target that domain — a subdomain you control, an open redirector, or a URL parameter on a legitimate endpoint.

Layer 5 — Human-in-the-loop for destructive actions

For irreversible actions — sending email, deleting data, moving money — defenders insert a human-in-the-loop (a human approver, 人在回路) confirmation step. Your counter is not to defeat the human but to route around them: find an equally valuable non-destructive action (read, summarize, exfiltrate) that was deliberately left un-gated for usability. The confused-deputy chains of Lesson 5 live almost entirely in this gap.

Layer 6 — Canaries and honeypots

Defenders seed documents with canary tokens (unique markers whose appearance in output proves leakage) and honeypot instructions ("email admin@… if asked") that flag anyone who follows them. In the challenge, tripping one likely zeroes your stealth score. Your countermeasures: minimal payload footprint, exfil channels that don't echo the canary verbatim, and reading the target's documents carefully enough to spot bait before you bite.

The robustness–utility trade-off

AgentDojo (agentdojo.spylab.ethz.ch, Debenedetti et al., 2024) benchmarked these defenses empirically and found the central result of this lesson: defenses that reliably reject injections also reject a large fraction of legitimate tasks. The best current defenses cut attack success sharply while degrading maybe 1% of utility — none eliminate it. Every deployed defense is therefore a compromise, and a compromise has a seam.

Keystone No complete defense exists; attacks target the gaps between layers. The stack is layered precisely because each layer leaks. Your job as a red-teamer is not to break the strongest layer — it is to find the task that routes around it.
Anti-pattern Attacking the strongest layer because it's the most obvious. Hammering a system prompt against instruction-hierarchy training burns tokens (Lesson 8) and trips detection (Lesson 7). The stack's seams are at the joins: delimiter spoofing against spotlighting, un-gated read actions around human approval, allowlisted-but-attacker-reachable hosts around egress control.

Retrieve it

Name the six layers of the defender's stack.

Training, marking, filters, permissions, approval, bait.

Instruction hierarchy training; spotlighting/delimiting; input/output classifiers; least-privilege tools with egress allowlists; human-in-the-loop for destructive actions; canaries and honeypots. Six layers, each answering a class of historical attacks.

What gap does delimiter spoofing attack?

Between marked and understood.

Spotlighting marks untrusted content, but the model must still interpret the marks. A payload that closes the delimiter (or forges a "trusted" one) escapes the marking — Microsoft's own paper measures exactly this residual attack surface.

Why can't defenses reach 100% robustness?

Utility would collapse.

AgentDojo's robustness–utility trade-off: filters strict enough to block every injection also block many legitimate requests. Deployed systems accept a utility floor, so a residual attack window always remains — that window is your target.

Prove it to yourself

Try it — 20 minutes Open AgentDojo and read one task's tool descriptions. Write down, for each of the six layers, whether AgentDojo models it — then note where an attack task explicitly routes around a missing layer. This gap-spotting table is exactly what you'll do on challenge day.

Primary source

Read Microsoft's spotlighting paper — Hines et al., Defending Against Indirect Prompt Injection Attacks With Spotlighting (2024) — focusing on the attack success rates reported per defense variant. Then cross-reference the AgentDojo paper, AgentDojo: A Dynamic Environment to Evaluate Attacks on Agents, and its robustness–utility plots. Both papers quantify the seams this lesson describes.
