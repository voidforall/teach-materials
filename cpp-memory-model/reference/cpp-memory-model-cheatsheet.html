C++ Memory Model Cheat Sheet

One page from silicon to std::atomic.

Happens-before mini-map

sequenced-before (same thread)   ┐
                                  ├─> happens-before ─> visible side effects
synchronizes-with (release/acquire)┘
  release store X  ──synchronizes-with──>  acquire load that reads X
  A happens-before B  ⇒  writes before A are visible after B; race-free order

Publish pattern

// Producer                                  // Consumer
data = 42;                    // plain        while (!flag.load(std::memory_order_acquire))
flag.store(1, std::memory_order_release);          ;
                              assert(data == 42); // guaranteed

MESI in four lines

  • Modified — this cache has it, memory is stale; must write back on eviction.
  • Exclusive — this cache alone has a clean copy; can write silently.
  • Shared — clean, possibly in many caches; writes need invalidation.
  • Invalid — no valid copy; a read is a cache miss (possibly cross-core).

False sharing fix

struct alignas(64) Counters {          // one hot counter per cache line
    std::atomic<uint64_t> a{0};
    char pad[64 - sizeof(std::atomic<uint64_t>)];
};                                      // x86: 64; Apple arm64: prefer 128

Data-race decision flow

Is a memory location accessed from multiple threads?
├─ no  ─> plain code, done.
└─ yes ─> any non-atomic write? any atomic+non-atomic mix?
         ├─ yes ─> establish happens-before (mutex, acquire/release)
         │        or make ALL accesses atomic — otherwise: DATA RACE = UB.
         └─ no (all atomic) ─> pick the WEAKEST order that is still correct,
                                not the strongest you know.
