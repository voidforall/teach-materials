happens-before 微型地图

sequenced-before（同线程内）  ┐
                              ├─> happens-before ─> 可见的副作用
synchronizes-with（release/acquire）┘
  release store X  ──synchronizes-with──>  读到 X 的 acquire load
  A happens-before B  ⇒  A 之前的写在 B 之后可见；无竞争的顺序

六个内存序

顺序可用于保证典型用途
relaxedload、store、RMW仅原子性 + 单一修改全序计数器、统计、自有下标
consumeload已弃用；按 acquire 处理别用
acquireload、RMW之后的读写不能前移到它之前发布的接收端、lock()
releasestore、RMW之前的读写不能后移到它之后发布的发送端、unlock()
acq_rel仅 RMW一次操作同时 acquire + release标志位的 fetch_add、算法中的 CAS
seq_cst全部acq_rel + 一个全局全序默认值；栅栏、成对标志、拿不准时

glibc malloc：大小 → 机制

请求大小机制free() 行为
≤ ~160 Btcache / fastbin（每线程、无锁）进空闲链表
~160 B – 1 KBsmallbin，每线程 arena进链表，arena 留着页
1 KB – 128 KBunsorted/largebin，arena 堆进链表；仅顶部裁剪
≥ 128 KB（M_MMAP_THRESHOLD）直接 mmapmunmap —— 立刻还给 OS

四行讲清 MESI

  • Modified（已修改）——本缓存持有，内存已过期；逐出时必须写回。
  • Exclusive（独占）——仅本缓存有干净副本；可静默写。
  • Shared（共享）——干净、可能在多个缓存中；写需先失效他核。
  • Invalid（无效）——无有效副本；读取即缓存 miss（可能跨核）。

数据竞争判定流程

同一内存位置会被多线程访问吗？
├─ 否 ─> 普通代码，完事。
└─ 是 ─> 存在非原子写？原子与非原子混用？
         ├─ 是 ─> 建立 happens-before（mutex、acquire/release），
         │        或把所有访问都改成原子 —— 否则：数据竞争 = UB。
         └─ 否（全原子）─> 选仍然正确的"最弱"内存序，
                            而不是你知道的最强内存序。
