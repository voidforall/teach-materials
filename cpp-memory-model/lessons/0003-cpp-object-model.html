The C++ Object Model

Memory is bytes; an object is a language-level fiction whose lifetime, placement, and shape the compiler reasons about — and optimizes against.

Four storage durations

The standard gives exactly four (storage duration): static (globals, static locals — lifetime = whole program), automatic (locals — the Lesson 2 stack frame), dynamic (new/delete — the heap), and thread_local (one object per thread — crucial later for per-thread data that needs no synchronization).

Lifetime is not scope

An object's lifetime begins when its initialization completes (and, with a nontrivial destructor, ends when the destructor call starts). Scope is a lexical region. They usually coincide — but not always, and the gap is where UB lives:

alignas(T) unsigned char buf[sizeof(T)];
T* p = new (buf) T{1};          // lifetime starts HERE (placement new)
p->~T();                        // lifetime ends HERE (explicit destructor call)
// scope still open, storage still there — but no T lives in buf

Reading *p after ~T() — or the classic "exit the scope, re-enter it, reuse the object you kept a pointer to" (e.g. reusing a std::optional's storage by hand) — is UB precisely because the compiler may cache the knowledge that the object is dead. std::launder is the escape hatch: it returns a pointer through which the new object is reachable, defeating the compiler's stale assumptions (see [intro.object]/7 on transparently replaceable objects — C++20 relaxed what reuse keeps alive, but only for same-type replacement).

Alignment and padding

Every object type has an alignment (alignof): a power-of-2 byte stride its address must respect, because CPUs load aligned words. Members are padded so each keeps its natural alignment, and sizeof is rounded up to alignof so arrays work:

struct S {
  char  c;   // offset 0
  int   i;   // offset 4 (3 bytes padding after c)
  char  d;   // offset 8
};           // sizeof = 12 (padded to align 4), not 6
static_assert(sizeof(S) == 12);        // x86-64/Linux — check by hand first!
static_assert(alignof(S) == 4);

#pragma pack / __attribute__((packed)) removes padding (wire formats!) at the cost of potentially unaligned, slower or trapping accesses; -Wpadded warns when the compiler inserts padding. malloc guarantees alignment for any type with alignment ≤ max_align_t (16 bytes on x86-64) — over-aligned types (alignas(64) for cache lines, Lesson 8) need aligned_alloc/operator new overloads, and std::align_val_t plumbing.

Why alignment matters here: hardware can only perform an atomic read-modify-write on a naturally divisible access. A 8-byte std::atomic<uint64_t> split across two cache lines cannot be lock-free. That's Lesson 5's opening problem.

KeystoneBytes are the hardware's objects; lifetime, alignment, and identity are the language's. The compiler's license to assume an object is alive (or dead, or aligned) is exactly the license that makes unsynchronized access explode — every later lesson is about that boundary.
Anti-patternEquating storage with objects: "the memory is still there, so my pointer is still valid." After the destructor runs, or after the optional is reset, the bytes remain but the object does not — and UB means the optimizer may act on that fact while your stale pointer still "works" in debug builds.

Retrieve it

When does lifetime begin?

When initialization completes

Not at scope entry, not at allocation — the constructor finishing is what creates the object; scope is just lexical syntax.

What does std::launder return?

A pointer to replacement

It returns a pointer through which a newly constructed object in reused storage is reachable, discarding cached assumptions about the dead one.

Why does sizeof pad?

So arrays stay aligned

sizeof must be a multiple of alignof, otherwise S[1] would break the alignment of every subsequent element.

Prove it to yourself

Try it — 10 minutes Compute by hand sizeof/alignof of: struct A { char c; double d; char e; };, struct B { double d; char c; char e; };, and struct C { char c; int i; double d; };. Then verify with a tiny program of static_assert(sizeof(A)==16 && alignof(A)==8) etc. (compile g++ -std=c++20 -Wpadded a.cpp on macOS arm64 or Linux — expected sizes 16/10→16/16; note ARM64 agrees with x86-64 on these). Reorder members to minimize padding and watch the warning disappear.

Why this matters for the mission

std::atomic is not magic bytes: it's an object with a lifetime, an alignment, and a hardware divisibility requirement. Data races are UB for the same reason stale lifetime is UB — the optimizer reasons about objects, not bytes. Lessons 4–5 build the formal model (happens-before) that makes such reasoning safe.
