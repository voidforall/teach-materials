大作业：无锁 SPSC 环形队列

课程的一切——顺序、原子变量的所有权、伪共享——压缩成正确的四十行：一个单生产者/单消费者环形队列，relaxed、acquire、release 各司其职，一个都不多余。

为什么 SPSC 是完美的大作业

一个生产者线程、一个消费者线程、一个有界缓冲。这个约束让每个下标只有唯一的写者，而单写者原子正是内存模型变得优雅的地方：下标的主人可以用 relaxed 更新自己的下标（暂时没别人需要与它排序），而读对方下标的一侧需要 acquire/release，让槽内容在下标移动之前/之后变得可见。没有 CAS、没有重试循环——每步操作在有限步内完成，所以它wait-free（无等待），而不只是 lock-free。

带注释的实现

#include <atomic>
#include <cstddef>
#include <array>
#include <optional>

// 缓存行填充（第 8 课）：head 与 tail 绝不能同行，
// 否则生产者与消费者会让该行在缓存之间打乒乓。
struct alignas(64) PaddedAtomic {                 // x86 用 64；Apple arm64
    std::atomic<size_t> v{0};                     // 用 128（fetchadd 碰撞域）
    PaddedAtomic() = default;
    PaddedAtomic(const PaddedAtomic& o) : v(o.v.load()) {}
};

template <typename T, size_t Cap>                 // Cap 必须是 2 的幂
class SpscRing {
    static_assert((Cap & (Cap - 1)) == 0);
    std::array<T, Cap> buf_{};
    PaddedAtomic head_{};   // 消费者侧位置（下一个读）
    PaddedAtomic tail_{};   // 生产者侧位置（下一个写）
    char pad_[64 - sizeof(PaddedAtomic) % 64];     // 数据也别挤上这两行

    static size_t idx(size_t v) { return v & (Cap - 1); }   // 廉价取模

public:
    bool push(const T& t) {
        size_t tail = tail_.v.load(std::memory_order_relaxed); // tail 归我
        size_t head = head_.v.load(std::memory_order_acquire); // 看见消费者腾位
        if (tail - head == Cap) return false;      // 满
        buf_[idx(tail)] = t;                       // 先写槽……
        tail_.v.store(tail + 1, std::memory_order_release);   // ……再发布
        return true;                               // release 与消费者的
    }                                              // acquire load 配对
    std::optional<T> pop() {
        size_t head = head_.v.load(std::memory_order_relaxed); // head 归我
        size_t tail = tail_.v.load(std::memory_order_acquire); // 看见生产者的数据
        if (head == tail) return std::nullopt;     // 空
        T t = buf_[idx(head)];                     // 先读槽……
        head_.v.store(head + 1, std::memory_order_release);   // ……再腾位
        return t;                                  // release 与生产者的
    }                                              // acquire load 配对
};

把注释读成前面课程的三条规则：(1)自己的下标用 relaxed——只有你写它，而你自己对它的读由 sequenced-before 排序；(2)对方的下标用 acquire——这次 load 必须与对面的 release store 同步，使 store 之前写入的槽内容在 load 之后可见（第 3 课的发布模式）；(3)自己的下标更新用 release——让对面 acquire 读到它时也看见你对槽做的事。下标单调递增、按掩码折进数组，所以容量判断 tail - head == Cap 在无符号回绕下依然成立。

为什么 alignas(64)？不加的话 head 和 tail 常常挤在同一缓存行；生产者写 tail、消费者写 head，这一行每次操作都在两核私有缓存间打乒乓（第 8 课的伪共享）——实测代价通常是 2–5 倍。可移植写法：alignas(std::hardware_destructive_interference_size)，以字面量 64/128 作后备，因为 libstdc++ 历史上把这个常量藏在特性宏后面。

为什么它不能朴素地推广

MPMC 破坏 wait-free。多生产者时"读 tail、检查、写槽、递增 tail"不再是单写者：两个生产者可能读到同一个 tail，通用解法只有 CAS 循环（compare_exchange_weak 直到成功），争用下会重试——lock-free 但不 wait-free，每次失败 CAS 都是白费的跨核流量。真正的 MPMC 队列（Vyukov、Folly）按生产者分格，把单写者性质夺回来。

ABA，以及我们为何躲开了。读到值 A、做点事、再"仅当仍是 A 才 CAS"的算法，会被 A→B→A 的变化欺骗——经典的"从空闲链表弹出两个节点"事故。我们的环形队列根本不比较下标：每一侧独占自己的下标，另一侧只读。单调计数器要绕完整个无符号范围（264 次操作）才回绕，"同值不同代"在实践中不可能。教训：带相等比较的 CAS 招 ABA；带计数器的所有权转移绕开它。

现代点缀。C++20 的 std::atomic_ref<T> 让你对非原子存储施加同样的纪律（比如槽位数组的视图）——顺序规则相同，生命周期规则要注意（被引用对象必须活得比所有 atomic_ref 长）。C++20 的 std::atomic::wait()/notify_one()/notify_all()（Linux 背后是 futex，Darwin 是 os_sync_wait_on_address 一类原语）给出这个队列的阻塞版：发现队列满的生产者可以在 tail 上 wait()，不必自旋也不必返回 false。

验证与基准

先证对：两线程推弹数百万个元素、累加校验和的测试，在 -fsanitize=thread 下必须干净（TSAN 理解 acquire/release——它会建模我们建立的 happens-before 边）。然后测吞吐。现代 x86-64 笔记本上、两线程经共享 L3 乒乓、每次一格的典型数字：

队列往返备注
std::mutex + deque~90–150 ns/op争用锁 + 分配器噪声
SPSC 环（填充）~20–40 ns/op两个原子 + 一对 acquire-load
SPSC 环（未填充）~60–150 ns/op伪共享主导
SPSC 环（批 64）~5–10 ns/元素摊薄跨核信号

正确的比较对象是你自己的机器；比值（互斥 ≈ 填充环的 3–5 倍）才是可移植的结论。没有 Linux 机器就在 godbolt 上复现。

Keystone单写者 ⇒ 自己 relaxed、发布 release、观察 acquire。一旦每块状态都有唯一主人，六个内存序的表坍缩成三个动词——是所有权、不是聪明，让环形队列 wait-free。
Anti-pattern因为"听起来更快"而上无锁。互斥队列正确、可调试、离最优只差 3–5 倍；搞砸的无锁队列是海森 bug 工厂。用互斥，直到性能分析器证明锁争用是瓶颈、而且你付得起验证成本（TSAN、litmus 测试、以及有能解释 diff 中每个内存序的同事来评审）。

检索它

为什么生产者读自己的 tail_ 可以用 relaxed？

只有生产者写 tail_，它自己的读由 sequenced-before 排序。

relaxed 仍保证原子性与单一全序修改；与其他线程的排序只在 acquire/release 边界需要，而槽内容可见性恰好由那里决定。

为什么 SPSC 环 wait-free，而 CAS 循环的 MPMC 队列不是？

SPSC 每次操作是固定的 load/store 序列；CAS 循环在争用下可能无界重试。

wait-free 指任何线程无论别人如何都能在有限步完成。每个下标的单一所有权彻底消灭了比较-重试的需要。

单调下标如何在这里绕开 ABA？

代码从不按下标做相等比较；所有权转让让"同值"不可能意味着"不同代"。

ABA 需要一次可能在旧值回收后仍成功的比较。环形队列的下标只增（每 2⁶⁴ 次操作才回绕），且每侧独占写自己的下标。

亲手验证

试一试 — 40 分钟

逐字敲入这个环形队列（敲，而不是粘贴，本身就是练习）。然后：

// bench.cpp — 一对线程，乒乓 N 个元素
// clang++ -std=c++20 -O2 -pthread bench.cpp && ./a.out
// clang++ -std=c++20 -O2 -g -fsanitize=thread bench.cpp && ./a.out   # TSAN 必须干净

SpscRing<uint64_t, 1024> q;
constexpr uint64_t N = 1'000'000;

void producer() {
    for (uint64_t i = 0; i < N; ) {
        if (q.push(i)) ++i;                    // 满时自旋重试即可
        else std::this_thread::yield();
    }
}
void consumer() {
    uint64_t expect = 0, sum = 0;
    while (expect < N) {
        if (auto v = q.pop()) { sum += *v; ++expect; }
    }
    assert(sum == N*(N-1)/2);                  // 正确性判据
}

预期：TSAN 干净；给这对生产者-消费者计时并打印 ns/op——填充过的环预期几十 ns，而你十行写出的 std::mutex+std::deque 版本 ~100+ ns。然后蓄意破坏：把生产者的 tail store 从 memory_order_release 改成 memory_order_relaxed。x86-64 上 store 本来就有 release 语义，可能继续通过——那是你的机器宽容，不是代码正确。跑 TSAN 版（TSAN 建模抽象机，会报出缺失的 release），或在 godbolt/qemu 上以 ARM64 编译同一份代码，或者把 payload 加宽到超过一条 store，让撕裂/重排在足够多次迭代后可观测。观察，还原，再跑一遍干净的。
