栈与堆：分配机制

栈分配是一次寄存器移动；堆分配是一个数据结构算法，外加迟早会来的缺页。

栈：分配 = 移动一个寄存器

每次调用压入一个栈帧（stack frame）。x86-64 SysV 的序言（prologue）通常是 push rbp; mov rbp,rsp; sub rsp,N —— "分配"N 个字节就是那条 sub。尾声（epilogue）：add rsp,N; pop rbp; ret（或 leave; ret）。释放同样免费。红区（red zone，RSP 之下 128 字节、叶子函数可直接使用而不必移动 SP）解释了为什么连 sub 都可以消失。在 Compiler Explorer 里编译下面这段，仔细看：

int sum(int a, int b) {      // x86-64 SysV: esi, edx
  int t = a + b;             // eax, esi, edx... 根本不需要帧
  return t;                  // 红区：什么都没压栈
}
int frame(int n) {
  int buf[64];               // sub rsp, 272 左右
  buf[0] = n;
  return buf[0];
}

因为分配只是指针算术，没有任何东西阻止你越界。内核在栈底放了一页 guard page，并施加大小上限——ulimit -s，Linux 上通常 8 MiB。冲破它（深递归、帧里巨大的 int buf[1<<20]）就得到 SIGSEGV；每线程栈通常小得多（pthread 默认约 8 MiB 虚拟内存，见 pthread_create(3)）。

堆：从 brk 到 bins

传统意义的堆是 brk 区域：推进和回退 program break。现代 glibc 的 malloc 在其上叠了真正的机器（见 glibc malloc internals wiki）：每线程的 tcache 缓存最近释放的小块（常见路径无锁），然后是 fastbins / smallbins / largebins，以及每线程 arena，使线程不必在一把锁上排队。大于动态 mmap 阈值（初始 128 KiB，M_MMAP_THRESHOLD）的分配绕过 bins 直接走 mmap(2) —— free 时立刻归还，这正是大块 new/delete 循环表现为 RSS 抖动、且每次复用都缺页的原因。

所以 new T(args) 的真实代价：(1) 分配器簿记（快：tcache 弹出），(2) 构造函数，(3) 可能要为分配器从未碰过的页触发缺页——第 1 课的法则：映射免费，缺页不免费。

// grow.cpp — g++ -O2 grow.cpp && ./a.out
#include <vector>
#include <chrono>
#include <cstdio>
int main() {
  using clk = std::chrono::steady_clock;
  auto t0 = clk::now();
  std::vector<int> v;
  for (int i = 0; i < 10'000'000; ++i) v.push_back(i);   // ~2x 的 memcpy 翻腾
  auto t1 = clk::now();
  std::vector<int> w;
  w.reserve(10'000'000);                                  // 一次 mmap，一轮缺页
  for (int i = 0; i < 10'000'000; ++i) w.push_back(i);
  auto t2 = clk::now();
  std::printf("push_back only : %lld ms\n",
    (long long)std::chrono::duration_cast<std::chrono::milliseconds>(t1-t0).count());
  std::printf("reserve first  : %lld ms\n",
    (long long)std::chrono::duration_cast<std::chrono::milliseconds>(t2-t1).count());
}

第二个实验：循环 new char[1<<20] / delete[]，同时观察 ps -o rss（或 grep VmRSS /proc/self/status）——超过 mmap 阈值时每轮都拆掉并重新缺页，RSS 震荡、fault 累积；低于阈值时，tcache/bins 复用热内存，RSS 平坦。

Keystone栈分配是指针算术；堆分配是一个最坏代价是缺页的库数据结构。 运行时你要付出的一切——锁、bin 遍历、清零、缺页——都在这条线的堆那一侧。
Anti-pattern"new 就是活得久一点的栈变量。" 不对：栈的代价是一次 sub，return 时整帧回收；堆的代价是分配器状态、构造函数和缺页，并且一块一块地归还。把两者等量齐观，会写出在分配上"随机"抖动的程序。

回忆检索

栈帧序言做什么？

保存 RBP、减 RSP

push rbp; mov rbp,rsp; sub rsp,N —— 那条 sub 就是 N 字节局部变量的全部分配成本。

malloc 的 tcache 是什么？

每线程空闲块缓存

一个实践中无锁的、缓存最近释放小块的结构，使"释放后立刻同尺寸再分配"的常见模式完全跳过 arena 加锁。

malloc 何时用 mmap？

超过约 128KB 阈值

大于动态 mmap 阈值（M_MMAP_THRESHOLD，初始 128 KiB）的请求直接映射，free 时归还操作系统。

亲手验证

试一试 — 15 分钟 运行上面的 grow.cpp —— 先 reserve 通常快 2–5 倍；用 profiler 确认差异来自几何增长带来的 memcpy 而不是 push_back 本身。然后在循环里跑 for(;;){ char* p = new char[1<<20]; p[0]=1; delete[] p; }，另一个终端里循环 ps -o rss= -p <pid>：Linux 上用 grep majflt /proc/<pid>/status 看缺页（macOS arm64 用 Instruments 的 Allocations）。换 new char[4096] 再试 —— RSS 和 fault 都变平，因为 bins 在回收热页。

为什么这对课程使命重要

无锁代码的动机通常是热路径上的分配：共享状态必须住在稳定的地方。确切知道 new 何时变成 mmap+缺页，就能解释为什么"每个元素都分配"的'无锁'队列可能输给不分配的阻塞队列——而第 3 课会把"你分配的那个对象"究竟是什么讲清楚。
