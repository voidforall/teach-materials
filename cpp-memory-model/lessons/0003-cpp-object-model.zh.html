C++ 对象模型

内存是字节；对象是语言层面的虚构——编译器会推理它的生命周期、放置与形状，并据此做优化。

四种存储期

标准只给出四种（storage duration，存储期）：static（全局变量、static 局部变量——生命周期 = 整个程序）、automatic（自动存储期的局部变量——即第 2 课的栈帧）、dynamic（动态存储期，new/delete——即堆）、以及 thread_local（线程存储期，每线程一个对象——之后做免同步的每线程数据时至关重要）。

生命周期不等于作用域

对象的生命周期（lifetime）在初始化完成时开始（对有非平凡析构函数的类型，析构调用开始时结束）。作用域只是一个词法区域。二者通常重合——但不总是，缝隙里藏着 UB：

alignas(T) unsigned char buf[sizeof(T)];
T* p = new (buf) T{1};          // 生命周期从这里开始（placement new，放置 new）
p->~T();                        // 生命周期到这里结束（显式析构调用）
// 作用域还开着，存储也还在 —— 但 buf 里已经没有 T 了

在 ~T() 之后读 *p——或者经典的"退出作用域再重进、复用你留了指针的对象"（比如手工复用 std::optional 的存储）——都是 UB，原因恰恰是编译器可能缓存"对象已死"这一事实。std::launder 是逃生门：它返回一个通过它可以访问新对象的指针，废掉编译器的过期假设（见 [intro.object]/7 关于透明可替换对象（transparently replaceable）——C++20 放宽了复用存储还能保住什么，但仅限同类型替换）。

对齐与填充

每个对象类型都有对齐（alignment，alignof）：地址必须满足的 2 的幂的字节间隔，因为 CPU 按对齐的字加载。成员之间会填充（padding），使各自保持自然对齐；sizeof 向上取整到 alignof 的倍数，否则数组没法工作：

struct S {
  char  c;   // 偏移 0
  int   i;   // 偏移 4（c 之后填充 3 字节）
  char  d;   // 偏移 8
};           // sizeof = 12（填充到对齐 4），不是 6
static_assert(sizeof(S) == 12);        // x86-64/Linux —— 先自己手算！
static_assert(alignof(S) == 4);

#pragma pack / __attribute__((packed)) 去掉填充（网络格式常用！），代价是可能未对齐的、更慢甚至触发异常的访问；-Wpadded 在编译器插入填充时告警。malloc 只保证对齐到 max_align_t（x86-64 上 16 字节）以内的任何类型——过度对齐（over-aligned）类型（为缓存行 alignas(64)，第 8 课）需要 aligned_alloc/operator new 重载，以及 std::align_val_t 的配套。

对齐在此处重要的原因：硬件只能对自然可分割（divisible）的访问执行原子读-改-写。一个跨两条缓存行的 8 字节 std::atomic<uint64_t> 不可能无锁。这就是第 5 课开篇的问题。

Keystone字节是硬件的对象；生命周期、对齐与同一性是语言的对象。 编译器有权假设一个对象活着（或死了、或对齐了），而未同步访问之所以爆炸，正是这个权利——后面每一课都在讲这条边界。
Anti-pattern把存储等同于对象："内存还在，所以我的指针还有效。" 析构函数跑完、optional 被 reset 之后，字节还在但对象没了——而 UB 意味着优化器可能据此行动，同时你的野指针在 debug 构建里"还能用"。

回忆检索

生命周期何时开始？

初始化完成之时

不是进入作用域时，也不是分配时——构造函数完成才创建对象；作用域只是词法。

std::launder 返回什么？

指向替换对象的指针

它返回一个通过它可以访问在复用存储中新建对象的指针，丢弃关于死对象的缓存假设。

sizeof 为何填充？

让数组保持对齐

sizeof 必须是 alignof 的倍数，否则 S[1] 会破坏后续每个成员的对齐。

亲手验证

试一试 — 10 分钟 手算 sizeof/alignof：struct A { char c; double d; char e; };、struct B { double d; char c; char e; };、struct C { char c; int i; double d; };。然后用一个 static_assert(sizeof(A)==16 && alignof(A)==8) 等小程序验证（在 macOS arm64 或 Linux 上 g++ -std=c++20 -Wpadded a.cpp——期望大小 16/10→16/16；这些例子上 ARM64 与 x86-64 一致）。重排成员以最小化填充，观察告警消失。

为什么这对课程使命重要

std::atomic 不是魔法字节：它是一个有生命周期、有对齐、有硬件可分割性要求的对象。数据竞争是 UB 的原因与过期生命周期是 UB 的原因相同——优化器推理的对象，而不是字节。第 4–5 课将建立让这种推理变安全的形式模型（happens-before）。
